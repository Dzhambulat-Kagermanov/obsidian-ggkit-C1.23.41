### Что такое SSH

**SSH (Secure Shell)** — протокол для безопасного удалённого управления компьютером по сети. Через него администратор подключается к серверу, запускает команды, передаёт файлы и настраивает сервисы.

SSH шифрует весь трафик между клиентом и сервером. Без шифрования пароли и команды можно было бы перехватить.

SSH работает поверх TCP, по порту **22** по умолчанию.

Компоненты:

|Компонент|Что это|
|---|---|
|`sshd`|Демон (программа) на сервере, принимает подключения|
|`ssh`|Клиент на компьютере администратора|
|`/etc/ssh/sshd_config`|Настройки сервера|
|`~/.ssh/config`|Настройки клиента|
|`~/.ssh/authorized_keys`|Список ключей, которым разрешён вход|
|`~/.ssh/known_hosts`|Список серверов, которым клиент уже доверяет|

### Как устроено подключение

Подключение проходит несколько этапов:

1. **TCP-соединение.** Клиент открывает соединение с сервером на порту 22.
2. **Согласование алгоритмов.** Стороны сообщают, какие алгоритмы шифрования они поддерживают, и выбирают общие.
3. **Обмен ключами (Key Exchange).** Клиент и сервер вычисляют общий секретный ключ сессии. Самое важное здесь: ключ не передаётся по сети. Каждая сторона вычисляет его сама, используя данные, которыми обменялась с другой стороной. Подслушивающий эти данные видит, но вычислить ключ не может.
4. **Проверка сервера.** Клиент убеждается, что подключается именно к нужному серверу.
5. **Аутентификация пользователя.** Сервер проверяет, что вы — это вы.
6. **Сессия.** Открывается оболочка (shell) или передаются файлы. Весь трафик зашифрован.

#### Что такое атака «человек посередине» (MITM)

Представьте, что между вами и сервером стоит злоумышленник. Он перехватывает ваше соединение и выдаёт себя за сервер. Вы отправляете ему пароль, он передаёт его настоящему серверу и получает доступ.

Защита от этого — **хостовый ключ** сервера. У каждого сервера есть уникальный ключ. Клиент запоминает его в `~/.ssh/known_hosts` при первом подключении. Если при следующем подключении ключ изменился, клиент выдаёт предупреждение и отказывается продолжать. Подменить сервер без этого ключа злоумышленник не может.

Проверка выглядит так:

- ключ совпадает — подключение продолжается;
- ключа нет в `known_hosts` — клиент спрашивает, доверяете ли вы этому серверу;
- ключ изменился — **предупреждение о возможной атаке**. Иногда причина безобидна: сервер переустановили. Но сначала нужно выяснить причину.

### Аутентификация пользователя

Сервер должен убедиться, что подключается нужный человек. Есть три способа:

**1. По ключу (`publickey`) — рекомендуемый способ**

У пользователя есть пара ключей: приватный (хранится только у него) и публичный (копируется на сервер). Клиент подписывает запрос приватным ключом, сервер проверяет подпись публичным. Приватный ключ по сети не передаётся.

**2. Интерактивный (`keyboard-interactive`)**

Сервер задаёт вопросы: пароль, код из приложения-генератора (2FA). Обычно работает через PAM — подсистему Linux для проверки пользователей.

**3. По паролю (`password`)**

Пароль отправляется внутри зашифрованного канала. Минус в том, что пароль можно подбирать (брутфорс). Ключ подобрать практически невозможно, поэтому парольный вход обычно отключают.
