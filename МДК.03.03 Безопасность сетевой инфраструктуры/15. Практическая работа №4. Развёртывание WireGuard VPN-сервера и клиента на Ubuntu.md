## Цель работы

Научиться устанавливать WireGuard, создавать ключи, настраивать VPN-сервер и VPN-клиент на Ubuntu Server, устанавливать защищённое соединение и проверять его работу.

## Предварительная информация

- **Proxmox:** `http://proxmox.ggkit.local:8006`.
- **Шаблон:** `students-ubuntu26.04-template`.
- Создайте **два полных клона (Full Clone)** шаблона:
  - `oaks-practicheskaya-rabota-4-server` — VPN-сервер;
  - `oaks-practicheskaya-rabota-4-client` — VPN-клиент.
- **Логин на обеих ВМ:** `user`.
- **Пароль:** `P@ssw0rd`.
- Адреса назначаются существующим DHCP-сервером. ip адреса на ВМ можно посмореть   через `ip -c -br a`
- В этой работе VPN создаётся **между двумя ВМ в лабораторной сети**. Публичный IP, проброс портов и доступ к интернету через VPN не требуются.
- **VPN-адрес сервера:** `10.8.0.1/24`.
- **VPN-адрес клиента:** `10.8.0.2/24`.
- **Порт WireGuard:** UDP `51820`.

## Требования к отчёту

Отчёт оформляется в **LibreOffice Writer**. Имя файла: `PR4-Имя_Фамилия.odt`.

1. **Титульный лист:** номер и название практической работы, ФИО и группа.
2. **Вторая страница:** цель работы и перечень заданий.
3. **Далее каждое задание с новой страницы:** что выполнено, использованные команды, читаемые скриншоты результатов и краткие пояснения.
4. **Последняя страница:** ответы на вопросы для защиты.

Отчёт необходимо загрузить в `Сеть для лабораторий/308а/С1.23.41`.

## Критерии оценки

- Две ВМ созданы и доступны по сети.
- WireGuard установлен на сервере и клиенте.
- Для каждой ВМ создана отдельная пара ключей; открытые ключи переданы через `scp`.
- Конфигурации содержат правильные адреса, ключи и параметры.
- VPN запускается, обмен пакетами и `ping` работают.
- Отчёт содержит команды, результаты и ответы на вопросы.

# Задания
## Задание 1. Создание виртуальных машин и проверка сети

Создайте в Proxmox два **полных клона (Full Clone)** шаблона `students-ubuntu26.04-template`: `oaks-practicheskaya-rabota-4-server` и `oaks-practicheskaya-rabota-4-client`. 

Запустите обе ВМ и войдите с логином `user` и паролем `P@ssw0rd`. 

Задайте имена компьютеров и определите основной IPv4-адрес сервера. В примере адрес сервера `192.168.1.10`; **обязательно замените его на ваш IP**.

На **сервере**:

```bash
sudo hostnamectl set-hostname wg-server
ip -c -br a
hostnamectl
```

На **клиенте**:

```bash
sudo hostnamectl set-hostname wg-client
ip -c -br a
hostnamectl
ping <IP сервера>
```

**Что отразить в отчёте:** Скриншот двух виртуальных машин в Proxmox, вывод `hostnamectl`, IP-адреса и результат `ping`.

## Задание 2. Установка WireGuard

На **обеих виртуальных машинах** обновите список пакетов, установите WireGuard и проверьте его версию.

На **обеих ВМ**:

```bash
sudo apt update
sudo apt install wireguard -y
wg --version
```

**Что отразить в отчёте:** Команды установки и версия WireGuard на сервере и клиенте.

## Задание 3. Создание ключей WireGuard

На каждой ВМ создайте собственную пару ключей. **Закрытый ключ** остаётся на своей машине; **открытый ключ** понадобится второй стороне. Для конфигурации сервера используйте открытый ключ клиента, для конфигурации клиента — открытый ключ сервера.

На **сервере**:

```bash
sudo install -d -m 700 /etc/wireguard
sudo sh -c 'umask 077; wg genkey > /etc/wireguard/server.key'
sudo sh -c 'wg pubkey < /etc/wireguard/server.key > /etc/wireguard/server.pub'
sudo cat /etc/wireguard/server.pub
sudo ls -l /etc/wireguard/
```

На **клиенте**:

```bash
sudo install -d -m 700 /etc/wireguard
sudo sh -c 'umask 077; wg genkey > /etc/wireguard/client.key'
sudo sh -c 'wg pubkey < /etc/wireguard/client.key > /etc/wireguard/client.pub'
sudo cat /etc/wireguard/client.pub
sudo ls -l /etc/wireguard/
```

### Передача открытых ключей между ВМ через SCP

В Proxmox используется консоль **noVNC**, поэтому копировать длинные ключи между окнами неудобно. Передадим файлы открытых ключей по сети с помощью `scp` (Secure Copy). Команда использует SSH для защищённой передачи файлов.

**1. Узнайте обычные IP-адреса обеих ВМ.** На каждой машине выполните:

```bash
ip -c -br a
```

**Замените их реальными IP-адресами своих ВМ.** Используйте адреса обычной сети, а не `10.8.0.1` и `10.8.0.2`: VPN пока не настроен.

**3. На клиенте передайте открытый ключ клиента на сервер:**

```bash
sudo cp /etc/wireguard/client.pub /tmp/client.pub
sudo chmod 644 /tmp/client.pub
scp /tmp/client.pub user@<IP сервера>:/home/user/client.pub
```

При первом подключении SSH может запросить подтверждение ключа хоста. Убедитесь, что IP-адрес указан правильно, и введите `yes`. Затем введите пароль пользователя `user` на сервере: `P@ssw0rd`. **При вводе пароля символы на экране не отображаются — это нормально.**

**4. На сервере проверьте получение ключа:**

```bash
cat /home/user/client.pub
```

**5. На сервере передайте открытый ключ сервера на клиент:**

```bash
sudo cp /etc/wireguard/server.pub /tmp/server.pub
sudo chmod 644 /tmp/server.pub
scp /tmp/server.pub user@<IP клиента>:/home/user/server.pub
```

Введите пароль `user` на клиентской ВМ, если SSH запросит его.

**6. На клиенте проверьте получение ключа:**

```bash
cat /home/user/server.pub
```

Теперь на сервере находится файл `/home/user/client.pub`, а на клиенте — `/home/user/server.pub`. Эти файлы содержат **только открытые ключи**. Для дальнейшей настройки можно вывести нужный ключ командой `cat` в том же окне noVNC.

**Что отразить в отчёте:** Команды генерации ключей, передачу через `scp`, проверку файлов `client.pub` и `server.pub` на принимающих ВМ. Закрытые ключи в отчёт не включайте.

## Задание 4. Настройка WireGuard-сервера

На **сервере** создайте файл `/etc/wireguard/wg0.conf`. Замените заполнители ключей на реальные значения. `PrivateKey` — именно содержимое закрытого ключа сервера, а не путь к файлу. Открытый ключ клиента уже передан на сервер в задании 3 и находится в `/home/user/client.pub`. Закрытый ключ сервера находится только на сервере.

На **сервере** откройте конфигурацию:

```bash
sudo nano /etc/wireguard/wg0.conf
```

Содержимое (замените значения в угловых скобках на соответствующие ключи):

```ini
[Interface]
Address = 10.8.0.1/24
ListenPort = 51820
PrivateKey = <ЗАКРЫТЫЙ_КЛЮЧ_СЕРВЕРА>

[Peer]
PublicKey = <ОТКРЫТЫЙ_КЛЮЧ_КЛИЕНТА>
AllowedIPs = 10.8.0.2/32
```

Для `PublicKey` на сервере выполните `cat /home/user/client.pub`. Для `PrivateKey` используйте содержимое `/etc/wireguard/server.key` на самом сервере (`sudo cat /etc/wireguard/server.key`). **Не вставляйте путь к файлу вместо ключа. Не снимайте скриншот с закрытым ключом.**

Сохраните файл (`Ctrl+O`, `Enter`, `Ctrl+X`) и выполните:

```bash
sudo chmod 600 /etc/wireguard/wg0.conf
sudo wg-quick up wg0
ip -c -br a
sudo wg show
sudo systemctl enable wg-quick@wg0
```

**Что отразить в отчёте:** Конфигурация сервера со скрытым значением `PrivateKey`, вывод `ip -c -br a` и `sudo wg show`.

## Задание 5. Настройка WireGuard-клиента

На **клиенте** создайте файл `/etc/wireguard/wg0.conf`. В параметре `Endpoint` укажите основной IP-адрес серверной ВМ, найденный в задании 1, и UDP-порт `51820`. `AllowedIPs = 10.8.0.0/24` означает, что через VPN пойдёт только трафик к VPN-подсети (Split Tunnel).

На **клиенте**:

```bash
sudo nano /etc/wireguard/wg0.conf
```

Конфигурация:

```ini
[Interface]
Address = 10.8.0.2/24
PrivateKey = <ЗАКРЫТЫЙ_КЛЮЧ_КЛИЕНТА>

[Peer]
PublicKey = <ОТКРЫТЫЙ_КЛЮЧ_СЕРВЕРА>
Endpoint = <IP сервера>:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
```

Замените IP-адрес серверной ВМ, а значения ключей — соответствующими ключами. Для `PrivateKey` используйте содержимое `/etc/wireguard/client.key` на клиенте; для `PublicKey` — содержимое полученного файла `/home/user/server.pub` на клиенте (`cat /home/user/server.pub`).

```bash
sudo chmod 600 /etc/wireguard/wg0.conf
sudo wg-quick up wg0
ip -c -br a
sudo wg show
```

**Что отразить в отчёте:** Конфигурация клиента со скрытым значением `PrivateKey`, адрес интерфейса `wg0` и результат запуска.

## Задание 6. Проверка VPN-соединения

Проверьте передачу пакетов через VPN в обе стороны, наличие `latest handshake` и счётчиков `transfer`. Затем перезапустите интерфейс клиента и повторите проверку.

На **клиенте**:

```bash
ping 10.8.0.1
sudo wg show
ip route get 10.8.0.1
```

На **сервере**:

```bash
ping 4 10.8.0.2
sudo wg show
```

На **клиенте** повторно запустите VPN:

```bash
sudo wg-quick down wg0
sudo wg-quick up wg0
ping 10.8.0.1
```

Успешный результат: `ping` проходит в обе стороны, а `sudo wg show` после обмена пакетами показывает `latest handshake` и ненулевые значения `transfer`.

Если `ping` не проходит, сначала проверьте основной IP сервера, доступность сервера по обычной сети, правильность открытых ключей, адреса `Endpoint` и состояние интерфейса `wg0` на обеих ВМ. Если на сервере включён UFW, проверьте разрешение входящих UDP-пакетов на порт `51820`.

**Что отразить в отчёте:** Результаты `ping` в обе стороны, вывод `wg show`, маршрут через `wg0` и проверка после перезапуска.
