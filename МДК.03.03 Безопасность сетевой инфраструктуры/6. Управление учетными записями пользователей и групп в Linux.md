## Введение

Управление учетными записями пользователей и групп — одна из базовых задач системного администрирования. В Linux для этого используется набор стандартных утилит (`useradd`, `usermod`, `userdel`, `groupadd`, `passwd`, `chage`), которые работают напрямую с конфигурационными файлами системы.

**Пользователь (user)** — это учетная запись, которая идентифицирует человека, процесс или сервис в системе. Каждый пользователь имеет:

- **UID (User ID)** — числовой идентификатор (например, `1000`)
- **Имя пользователя** — текстовое представление (например, `john`)
- **Домашнюю директорию** — личное пространство для файлов (`/home/john`)
- **Оболочку (shell)** — программу, которая выполняется при входе (`/bin/bash`)

**Группа (group)** — это набор пользователей для упрощения управления правами доступа. Каждая группа имеет:

- **GID (Group ID)** — числовой идентификатор
- **Имя группы** — текстовое представление

**Типы пользователей:**

- **Обычные пользователи** (UID 1000+) — люди, которые работают с системой
- **Системные пользователи** (UID 1-999) — сервисы и приложения (например, `nginx`, `mysql`)
- **root** (UID 0) — суперпользователь с полным доступом

## Создание пользователей:

### Что происходит при создании пользователя

Когда вы создаете пользователя, система выполняет несколько действий:

1. **Добавляет запись в `/etc/passwd`** — основной файл с информацией о пользователях
2. **Создает запись в `/etc/shadow`** — файл с хешами паролей (доступен только root)
3. **Создается группа название которой соответствует имени пользователя** — добавляет запись в `/etc/group`
4. **Создает домашнюю директорию** (если указан флаг `-m`) — копирует содержимое из `/etc/skel`
5. **Устанавливает права доступа** на домашнюю директорию

`useradd` — это низкоуровневая утилита, которая создает пользователя без лишних вопросов.

```bash
# Создание пользователя с настройками по умолчанию
useradd john

# Создание пользователя с домашней директорией и bash-оболочкой
useradd -m -s /bin/bash john

# Создание системного пользователя (без домашней директории, UID из диапазона 100-999)
useradd -r -s /sbin/nologin app-service

# Полное указание всех параметров
useradd -m -s /bin/bash -c "John Smith, IT Department" -G developers,sudo -u 1500 john

# Проверка созданного пользователя
id john
```

### Ключевые флаги `useradd`

| Опция             | Описание                                                               | Пример использования            |
| ----------------- | ---------------------------------------------------------------------- | ------------------------------- |
| `-m`              | Создать домашнюю директорию (`/home/username`)                         | `useradd -m john`               |
| `-M`              | Не создавать домашнюю директорию (даже если настроено по умолчанию)    | `useradd -M john`               |
| `-s <shell>`      | Указать оболочку по умолчанию                                          | `useradd -s /bin/zsh john`      |
| `-g <group>`      | Указать основную группу (GID)                                          | `useradd -g developers john`    |
| `-G <groups>`     | Список дополнительных групп через запятую                              | `useradd -G docker,sudo john`   |
| `-c "<comment>"`  | GECOS-поле (описание, полное имя, контакт)                             | `useradd -c "John Smith" john`  |
| `-u <UID>`        | Явно задать UID (редко, для совместимости между системами)             | `useradd -u 1500 john`          |
| `-r`              | Создать системного пользователя (UID 100-999, без домашней директории) | `useradd -r nginx`              |
| `-d <path>`       | Указать путь к домашней директории (вместо `/home/user`)               | `useradd -d /srv/john john`     |
| `-e <YYYY-MM-DD>` | Дата истечения срока действия аккаунта                                 | `useradd -e 2027-01-01 john`    |
| `-N`              | Не создавать одноимённую группу для пользователя                       | `useradd -N -g developers john` |

### Автоматическое создание группы

При создании нового пользователя в Linux автоматически создается одноименная группа. Эта стандартная политика безопасности называется **User Private Group (UPG)**.

**Как это работает:**

- **Главная группа:** По умолчанию создается группа с тем же именем, что и логин. Пользователь автоматически становится ее единственным участником.
- **Права доступа:** Эта схема обеспечивает безопасные настройки по умолчанию: созданные файлы доступны только этому пользователю и его группе.

```bash
# Создаем пользователя john
useradd -m john

# Проверяем, что создалась группа john
getent group john
# Вывод: john:x:1001:

# Проверяем основную группу пользователя
id john
# Вывод: uid=1001(john) gid=1001(john) groups=1001(john)
```

## Модификация учетных записей:

Команда `usermod` позволяет изменить практически любой параметр существующего пользователя. **Что происходит под капотом:** команда редактирует файлы `/etc/passwd`, `/etc/shadow` и `/etc/group`.

```bash
# Смена оболочки пользователя
# Что происходит: меняется поле в /etc/passwd
usermod -s /bin/zsh john

# Смена основной группы
# Что происходит: меняется GID в /etc/passwd
usermod -g developers john

# Добавление пользователя в дополнительные группы (ВАЖНО: использовать -a!)
# Что происходит: пользователь добавляется в список участников группы в /etc/group
usermod -aG docker,wheel john

# Смена домашней директории с переносом содержимого
# Что происходит: меняется путь в /etc/passwd, файлы переносятся из старой директории
usermod -d /srv/john -m john

# Блокировка учетной записи
# Что происходит: в /etc/shadow перед хешем пароля добавляется символ '!'
usermod -L john

# Разблокировка учетной записи
# Что происходит: символ '!' удаляется из /etc/shadow
usermod -U john

# Изменение GECOS-комментария (информация о пользователе)
# Что происходит: меняется поле в /etc/passwd
usermod -c "John Smith, Senior DevOps" john

# Установка даты истечения срока действия
# Что происходит: меняется поле в /etc/shadow
usermod -e 2027-01-01 john

# Полное отключение учетной записи (блокировка + истечение пароля)
usermod -L -e 1 john
```

>[!DANGER] Критически важный флаг `-a` (append)
>При добавлении пользователя в дополнительные группы **всегда** используйте `usermod -aG <groups> <user>`. Без `-a` флаг `-G` **перезаписывает** все дополнительные группы указанными, удаляя пользователя из остальных групп. Это частая причина потери доступа.
>```bash
># ❌ ОПАСНО: удалит пользователя из всех групп, кроме docker
usermod -G docker john
>
># ✅ ПРАВИЛЬНО: добавит в docker, сохранив остальные группы
usermod -aG docker john
>
># Посмотреть группы
>groups john
>id john
>```

**Почему это важно:** Если пользователь был в группах `sudo`, `docker`, `developers`, а вы выполнили `usermod -G docker john`, он останется только в группе `docker` и потеряет доступ к `sudo`. Это может привести к потере административного доступа к серверу.

## Удаление учетных записей: `userdel`

### Базовое удаление

```bash
# Базовое удаление (файлы пользователя остаются)
# Что происходит: удаляется запись из /etc/passwd и /etc/shadow, 
# домашняя директория и файлы остаются
userdel john

# Полное удаление с домашней директорией и почтовым буфером
# Что происходит: удаляется запись из файлов + домашняя директория + /var/spool/mail/john
userdel -r john

# Удаление с принудительным удалением всех файлов, принадлежащих пользователю
# Что происходит: удаляет все файлы, даже если пользователь сейчас в системе
userdel -r -f john
```

## Управление группами

### Что такое основная и дополнительные группы

В Linux каждый пользователь принадлежит:

- **Одной основной группе (primary group)** — используется для создания новых файлов. Файлы получают GID этой группы.
- **Нескольким дополнительным группам (secondary groups)** — дают дополнительные права доступа.

```
# Пользователь john
id john
# uid=1000(john) gid=1000(john) groups=1000(john),27(sudo),999(docker)
#                 ^^^^^^^^^^^^^^      ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
#                 Основная группа     Дополнительные группы
```

### Создание групп:

```bash
# Создание обычной группы
# Что происходит: добавляется запись в /etc/group
groupadd developers

# Создание системной группы (GID из диапазона 1-999)
# Системные группы используются для сервисов
groupadd -r service-group

# Явное указание GID
# Полезно для синхронизации между серверами (например, в NFS)
groupadd -g 2000 devops-team

# Создание группы с паролем (редко используется)
# Позволяет пользователям вступать в группу, зная пароль группы
groupadd -p '$6$xyz...hashed' restricted-group
```

### Модификация групп:

```bash
# Переименование группы
# Что происходит: меняется имя в /etc/group
groupmod -n dev-team developers

# Изменение GID группы
# ВНИМАНИЕ: требует обновления прав на файлах!
groupmod -g 3000 devops-team

# После изменения GID нужно обновить владельца файлов
find / -gid 2000 -exec chgrp -h devops-team {} \; 2>/dev/null
```

### Удаление групп:

```bash
# Удаление группы
# Нельзя удалить основную группу пользователя!
groupdel old-group

# Если группа является основной для какого-то пользователя, сначала измените её:
usermod -g new-primary-group affected-user
groupdel old-group
```

## Управление паролями и политиками

Linux **никогда не хранит пароли в открытом виде**. Вместо этого хранится **хеш** — результат одностороннего математического преобразования.

**Как это работает:**

1. Пользователь вводит пароль `mypassword123`
2. Система применяет хеш-функцию (например, SHA-512) с случайными данными
3. Результат (например, `$6$xyz...abc`) сохраняется в `/etc/shadow`
4. При следующем входе система снова хеширует введенный пароль и сравнивает с сохраненным

**Почему это важно:**

- Если злоумышленник получит доступ к `/etc/shadow`, он не узнает пароли
- Хеши нельзя "расшифровать" обратно в пароль
- Но их можно "взломать" перебором (brute-force), поэтому важны сложные пароли
