## Задания

### Задание 1. Первоначальное подключение и изучение `known_hosts`

**Цель:** Получить IP-адреса виртуальных машин, установить первое соединение и понять механизм проверки хостового ключа.

1. Войдите в обе виртуальные машины (`client` и `server`) через консоль Proxmox.
2. На обеих машинах выполните команду для просмотра IP-адреса:

```bash
ip -c -br a
```

_(Запишите IP-адрес bsi-practicheskaya-rabota-3-server, он понадобится далее. Допустим, это `192.168.1.50`)_.

3. На машине **client** попытайтесь подключиться к серверу по паролю:

```bash
ssh user@<IP_адрес_сервера>
```

_Можно посмотреть что knowk_hosts изначально пустой_

```bash
cat ~/.ssh/known_hosts
```

4. При первом подключении система выдаст предупреждение о невозможности проверить подлинность хоста. Введите `yes` для продолжения.
5. Введите пароль `P@ssw0rd`.
6. Успешно войдя на сервер, выполните команду `exit` для возврата на клиент.
7. На машине **client** просмотрите содержимое файла доверенных хостов:

```bash
cat ~/.ssh/known_hosts
```

**Что отразить в отчёте:** Скриншот процесса первого подключения с предупреждением, вывод команды `cat ~/.ssh/known_hosts` и краткое объяснение, зачем нужен этот файл (защита от MITM-атаки).

### Задание 2. Настройка аутентификации по ключу (Ed25519)

**Цель:** Отказаться от небезопасного ввода пароля и настроить вход по криптографическому ключу.

1. На машине **client** сгенерируйте пару ключей Ed25519 с комментарием (укажите свою фамилию-имя за место **student**):

```bash
ssh-keygen -t ed25519 -C "student@lab.local" -f ~/.ssh/id_ed25519
```

_(Нажмите Enter, чтобы не устанавливать passphrase, так как это учебная среда)._

2. Установите строгие права доступа на файлы ключей (это обязательное требование SSH):

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519
chmod 644 ~/.ssh/id_ed25519.pub
```

3. Скопируйте публичный ключ на сервер с помощью утилиты `ssh-copy-id` (потребуется ввести пароль один раз):

```
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@<IP_адрес_сервера>
```

4. Попробуйте подключиться к серверу снова:

```bash
ssh user@<IP_адрес_сервера>
```

_(Подключение должно пройти без запроса пароля)._

**Что отразить в отчёте:** Скриншоты генерации ключа, изменения прав (`ls -la ~/.ssh`) и успешного входа без пароля.

### Задание 3. Усиление безопасности сервера (`sshd_config`)

**Цель:** Запретить аутентификацию по паролю и ограничить доступ только для авторизованных пользователей.

1. На машине **server** откройте конфигурационный файл:

```bash
sudo nano /etc/ssh/sshd_config
```

2. Найдите и измените следующие параметры (если они закомментированы `#`, раскомментируйте их):

```
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
MaxAuthTries 3
```

3. Для дополнительной проверки создайте группу `ssh-users` и добавьте в неё пользователя `user`:

```bash
sudo groupadd ssh-users
sudo usermod -aG ssh-users user
```

Добавьте в конец файла `sshd_config` строку:

```
AllowGroups ssh-users
```

4. Сохраните файл (`Ctrl+O`, `Enter`, `Ctrl+X`).

5. Перезапустите службу SSH согласно рекомендациям для Ubuntu 26.04:

```bash
sudo systemctl stop ssh.socket
sudo systemctl disable ssh.socket
sudo systemctl enable --now ssh.service
```

6. **Проверка:** Откройте **новую** вкладку терминала на машине **client** и попробуйте подключиться к серверу. Подключение должно пройти успешно по ключу.

7. **Проверка отказа:** Попробуйте подключиться с несуществующего пользователя или принудительно запросить пароль (`ssh -o PreferredAuthentications=password user@<IP_сервера>`). Должно быть отказано.

**Что отразить в отчёте:** Скриншот измененного файла `sshd_config`, вывод команд управления службой и скриншот успешного подключения в новой сессии.

### Задание 4. Настройка клиента для удобства работы (`~/.ssh/config`)

**Цель:** Настроить алиасы для быстрого подключения и предотвратить ошибки "Too many authentication failures".

1. На машине **client** создайте или откройте файл конфигурации клиента:

```bash
nano ~/.ssh/config
```

2. Добавьте следующую конфигурацию (замените `<IP_адрес_сервера>` на реальный):

```
Host lab-server
   HostName <IP_адрес_сервера>
   User user
   IdentityFile ~/.ssh/id_ed25519
   IdentitiesOnly yes
```

3. Сохраните файл и установите на него правильные права:

```bash
chmod 600 ~/.ssh/config
```

4. Проверьте работу конфигурации, подключившись просто по имени хоста:

```bash
ssh lab-server
```

**Что отразить в отчёте:** Содержимое файла `~/.ssh/config` и скриншот успешного подключения по команде `ssh lab-server`. Объясните, зачем нужна директива `IdentitiesOnly yes`.

### Задание 5. Передача файлов и базовая диагностика

**Цель:** Научиться копировать файлы по защищенному каналу и читать логи при возникновении проблем.

1. На машине **client** создайте тестовый файл:

```bash
echo "Это тестовый файл для SCP" > test_file.txt
```

2. Скопируйте этот файл на сервер в домашнюю директорию пользователя:

```bash
scp test_file.txt lab-server:~/
```

3. Проверьте наличие файла на сервере (подключившись через `ssh lab-server` и выполнив `ls -l`).

4. Скопируйте файл с сервера обратно на клиент, но с новым именем:

```bash
scp lab-server:~/test_file.txt ./test_file_from_server.txt
```

5. Для понимания процесса диагностики выполните команду подключения с максимальным уровнем детализации (вывод можно не весь вставлять в отчет, только первые 15-20 строк):

```bash
ssh -vvv lab-server
```

**Что отразить в отчёте:** Скриншоты передачи файлов в обе стороны с подтверждением их наличия. Краткий вывод команды `ssh -vvv` с пояснением, на каком этапе происходит аутентификация по ключу.
