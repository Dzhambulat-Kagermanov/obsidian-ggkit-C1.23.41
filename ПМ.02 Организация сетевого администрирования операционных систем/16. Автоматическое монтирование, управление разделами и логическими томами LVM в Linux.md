Для работы выполнения команд допустим что есть следующие разделы.

| Устройство | Объём  | Назначение                   |
| ---------- | ------ | ---------------------------- |
| `/dev/sda` | 30 ГиБ | Системный диск, не изменяем  |
| `/dev/sdb` | 10 ГиБ | Разметка, ext4, монтирование |
| `/dev/sdc` | 8 ГиБ  | Первый диск LVM              |
| `/dev/sdd` | 12 ГиБ | Расширение LVM               |

Имена устройств являются примером. На конкретной виртуальной машине они могут отличаться.

## 1. Автоматическое монтирование файловых систем

### 1.1. Назначение автоматического монтирования

<mark style="background:#fff88f">Автоматическое монтирование — подключение файловой системы к заданному каталогу без ручного выполнения команды `mount` после каждой загрузки Linux.</mark>

При обычном монтировании:

```bash
sudo mount /dev/sdb1 /srv/data
```

<mark style="background:#fff88f">Файловая система подключается на время работы системы. После перезагрузки такое подключение обычно не восстанавливается само по себе. Для постоянного монтирования используется файл `/etc/fstab`.</mark>

<mark style="background:#fff88f">`/etc/fstab` (File Systems Table) — конфигурационный файл Linux, содержащий сведения о файловых системах, точках монтирования и параметрах их подключения.</mark>

Пример записи в `/etc/fstab`:

```bash
UUID=4f2a8d30-... /srv/data ext4 defaults 0 2
```

<mark style="background:#fff88f">Строка состоит из шести полей:</mark>

| <mark style="background:#fff88f">Поле</mark>        | <mark style="background:#fff88f">Назначение</mark>                     |
| --------------------------------------------------- | ---------------------------------------------------------------------- |
| <mark style="background:#fff88f">`UUID=...`</mark>  | <mark style="background:#fff88f">Идентификатор файловой системы</mark> |
| <mark style="background:#fff88f">`/srv/data`</mark> | <mark style="background:#fff88f">Точка монтирования</mark>             |
| <mark style="background:#fff88f">`ext4`</mark>      | <mark style="background:#fff88f">Тип файловой системы</mark>           |
### 1.2. Настройка автоматического монтирования

<mark style="background:#fff88f">Предположим, на разделе `/dev/sdb1` уже создана файловая система ext4.</mark>

<mark style="background:#fff88f">Получим UUID:</mark>

```bash
sudo blkid /dev/sdb1
```

Пример результата:

```bash
/dev/sdb1: UUID="4f2a8d30-..." TYPE="ext4"
```

<mark style="background:#fff88f">Создадим точку монтирования, если её ещё нет:</mark>

```bash
sudo mkdir -p /srv/data
```

Сохраним резервную копию конфигурации:

```bash
sudo cp /etc/fstab /etc/fstab.bak
```

Откроем файл:

```bash
sudo nano /etc/fstab
```

<mark style="background:#fff88f">Добавим в `/etc/fstab` строку с настоящим UUID:</mark>

```bash
UUID=ВАШ_UUID /srv/data ext4 defaults 0 2
```

Сохраним изменения.

>[!DANGER] <mark style="background:#fff88f">Опасность редактирования `/etc/fstab`</mark>
><mark style="background:#fff88f">Редактирование файла `/etc/fstab` (таблицы файловых систем в Linux) сопряжено с высоким риском, так как **любая ошибка в нем может привести к невозможности загрузки операционной системы**.</mark>
>
><mark style="background:#fff88f">После сохранения изменений выполните команду проверки fstab файла:</mark> 
>
>```bash
>findmnt --verify
>```
>
><mark style="background:#fff88f">Или можно проверить правильность fstab сразу смонтировав все диски</mark>
>
>```bash
>sudo mount -a
>```
><mark style="background:#fff88f">Эта команда пытается смонтировать всё, что описано в `fstab`. Если она выдаст ошибку — **исправляйте её немедленно**. Если команда выполнилась молча — всё в порядке, можно перезагружаться.</mark>

<mark style="background:#fff88f">После редактирования `/etc/fstab`:</mark>

```bash
sudo systemctl daemon-reload
```

## 2. Разметка дисков с помощью fdisk

### 2.1. Назначение fdisk

В отличие от команд, где вся операция задаётся одной строкой, `fdisk` открывает интерактивный интерфейс. Администратор последовательно выбирает действия и подтверждает запись изменений.

<mark style="background:#fff88f">Для просмотра дисков:</mark>

```bash
sudo fdisk -l
```

Для открытия конкретного диска:

```bash
sudo fdisk /dev/sdb
```

### 2.2. Основные команды fdisk

| Команда | Назначение                         |
| ------- | ---------------------------------- |
| `m`     | Показать справку                   |
| `p`     | Показать текущую таблицу разделов  |
| `g`     | Создать таблицу GPT                |
| `o`     | Создать таблицу MBR                |
| `n`     | Создать раздел                     |
| `d`     | Удалить раздел                     |
| `t`     | Изменить тип раздела               |
| `l`     | Показать доступные типы разделов   |
| `F`     | Показать свободное пространство    |
| `v`     | Проверить таблицу разделов         |
| `w`     | Записать изменения на диск и выйти |
| `q`     | Выйти без сохранения изменений     |

До выполнения `w` большинство изменений разметки остаются в рабочей копии таблицы разделов.

>[!WARNING] Важно:
>Запись новой таблицы разделов или удаление разделов может сделать существующие данные недоступными.

Задача: на диске `/dev/sdb` объёмом 10 ГБ создать:
- Первый раздел — 4 ГБ.
- Второй раздел — всё оставшееся свободное пространство.

#### <mark style="background:#fff88f">Шаг 1. Запуск fdisk</mark>

```bash
sudo fdisk /dev/sdb
```

Появится приглашение:

```
Command (m for help):
```

#### <mark style="background:#fff88f">Шаг 2. Создание GPT</mark>

<mark style="background:#fff88f">Вводим:</mark>

```
Command (m for help): g
```

<mark style="background:#fff88f">`g` создаёт новую таблицу разделов GPT.</mark>

#### <mark style="background:#fff88f">Шаг 3. Создание первого раздела</mark>

<mark style="background:#fff88f">Вводим:</mark>

```
Command (m for help): n
Partition number (default 1):
First sector:
Last sector: +4G
```

- <mark style="background:#fff88f">`n` — создать раздел.</mark>
- <mark style="background:#fff88f">`Partition number` — номер раздела; нажимаем Enter.</mark>
- <mark style="background:#fff88f">`First sector` — первый сектор; нажимаем Enter.</mark>
- <mark style="background:#fff88f">`Last sector` — последний сектор или размер раздела.</mark>
- <mark style="background:#fff88f">`+4G` — выделить разделу 4 ГБ.</mark>

<mark style="background:#fff88f">Получим `/dev/sdb1` при `lsblk`.</mark>

#### <mark style="background:#fff88f">Шаг 4. Создание второго раздела на всё оставшееся место</mark>

<mark style="background:#fff88f">Снова вводим `n`:</mark>

```
Command (m for help): n
Partition number (default 2):
First sector:
Last sector:
```

На всех трёх запросах нажимаем Enter. Именно последний Enter позволяет второму разделу занять всё оставшееся доступное пространство.

#### <mark style="background:#fff88f">Шаг 5. Сохранение изменений</mark>

<mark style="background:#fff88f">Если всё правильно:</mark>

```
Command (m for help): w
```

<mark style="background:#fff88f">`w` записывает таблицу разделов на диск и завершает работу `fdisk`. Если обнаружена ошибка, вместо `w` вводим:</mark>

```
Command (m for help): q
```

<mark style="background:#fff88f">`q` позволяет выйти без сохранения изменений разметки.</mark>

#### Шаг 6. Проверка после записи

```bash
lsblk /dev/sdb
```

<mark style="background:#fff88f">Ожидаемый результат:</mark>

```bash
NAME   SIZE TYPE
sdb     10G disk
├─sdb1   4G part
└─sdb2   6G part
```

## 7. Управление логическими томами LVM

- <mark style="background:#fff88f">**PV (Physical Volume)** — физический том. Это диск или раздел, подготовленный для использования LVM.</mark>

- <mark style="background:#fff88f">**VG (Volume Group)** — группа томов. Она объединяет пространство одного или нескольких физических томов в общий пул.</mark>

- <mark style="background:#fff88f">**LV (Logical Volume)** — логический том. Это виртуальное блочное устройство, которое администратор создаёт из пространства группы томов. На нём можно создать файловую систему и смонтировать её.</mark>

### 7.1. Установка LVM

<mark style="background:#fff88f">Пакет `lvm2` содержит инструменты создания и управления PV, VG и LV.</mark>

```bash
sudo apt update
sudo apt install lvm2 -y
```

### 7.2. Создание раздела для LVM

<mark style="background:#fff88f">В для создания LVM тома используется `/dev/sdc`  диск объёмом 8 ГБ. Запустим:</mark>

```bash
sudo fdisk /dev/sdc
```

```
Command (m for help): g
```

<mark style="background:#fff88f">Создадим раздел на всё пространство:</mark>

```
Command (m for help): n
Partition number (1-128, default 1): [Enter]
First sector (...): [Enter]
Last sector (...): [Enter]
```

<mark style="background:#fff88f">Сохраним:</mark>

```
Command (m for help): w
```

<mark style="background:#fff88f">Обновим сведения ядра:</mark>

```bash
sudo partprobe /dev/sdc
sudo udevadm settle
```

### 7.3. Создание физического тома PV

>[!INFO] `pvcreate`
>Команда инициализации физического тома LVM.

<mark style="background:#fff88f">Создаем PV</mark>

```bash
sudo pvcreate /dev/sdc1
```


>[!INFOR] `pvs`
>Команда краткого просмотра физических томов LVM.

<mark style="background:#fff88f">Проверим:</mark>

```bash
sudo pvs
```

### 7.4. Создание группы томов VG

>[!INFO] `vgcreate`
>Команда создания группы томов.

<mark style="background:#fff88f">Создаем VG</mark>

```bash
sudo vgcreate vg_storage /dev/sdc1
```

- <mark style="background:#fff88f">`vg_storage` — имя группы.</mark>
- <mark style="background:#fff88f">`/dev/sdc1` — физический том.</mark>

>[!INFO] `vgs`
>Команда просмотра групп томов.



<mark style="background:#fff88f">Проверим:</mark>

```bash
sudo vgs
```

Теперь у нас есть группа `vg_storage` с доступным пространством около 8 ГБ.

### 7.5. Создание логического тома LV

>[!INFO] `lvcreate`
>Команда создания логического тома.

<mark style="background:#fff88f">Создадим том размером 5 ГБ:</mark>

```bash
sudo lvcreate -L 5G -n lv_data vg_storage
```

- <mark style="background:#fff88f">`-L 5G` — размер.</mark>
- <mark style="background:#fff88f">`-n lv_data` — имя тома.</mark>
- <mark style="background:#fff88f">`vg_storage` — имя группы.</mark>

<mark style="background:#fff88f">Проверим:</mark>

```bash
sudo lvs
```

<mark style="background:#fff88f">Созданный том доступен по пути:</mark>

```
/dev/vg_storage/lv_data
```

### 7.6. Создание файловой системы и монтирование

<mark style="background:#fff88f">Создадим ext4:</mark>

```bash
sudo mkfs.ext4 /dev/vg_storage/lv_data
```

<mark style="background:#fff88f">Создадим точку монтирования:</mark>

```bash
sudo mkdir -p /srv/storage
```

<mark style="background:#fff88f">Смонтируем:</mark>

```bash
sudo mount /dev/vg_storage/lv_data /srv/storage
```

<mark style="background:#fff88f">Проверим:</mark>

```bash
df -hT /srv/storage
```

## 8. Расширение LVM за счёт второго диска

### 8.1. Назначение расширения

<mark style="background:#fff88f">Расширение LVM — увеличение доступного дискового пространства путём добавления физических томов в группу VG и последующего увеличения логических томов LV.</mark>

<mark style="background:#fff88f">Предположим, что логический том `/dev/vg_storage/lv_data` имеет размер 5 ГБ. На нём хранятся файлы приложения. Свободного места становится недостаточно.</mark>

<mark style="background:#fff88f">К серверу подключают дополнительный диск `/dev/sdd` объёмом 12 ГБ. Наша задача — увеличить существующий том без удаления данных.</mark>

### 8.2. Подготовка нового диска через fdisk

<mark style="background:#fff88f">Запустим `fdisk`:</mark>

```bash
sudo fdisk /dev/sdd
```

<mark style="background:#fff88f">Создадим GPT:</mark>

```
Command (m for help): g
```

<mark style="background:#fff88f">Создадим раздел на всё свободное пространство:</mark>

```
Command (m for help): n
Partition number (1-128, default 1): [Enter]
First sector (...): [Enter]
Last sector (...): [Enter]
```

<mark style="background:#fff88f">Сохраним:</mark>

```bash
Command (m for help): w
```

<mark style="background:#fff88f">Обновим таблицу разделов:</mark>

```bash
sudo partprobe /dev/sdd
sudo udevadm settle
```

<mark style="background:#fff88f">Проверим:</mark>

```bash
lsblk /dev/sdd
```

<mark style="background:#fff88f">Теперь доступен раздел `/dev/sdd1`.</mark>

### 8.3. Добавление нового PV

<mark style="background:#fff88f">Создадим физический том:</mark>

```bash
sudo pvcreate /dev/sdd1
```

<mark style="background:#fff88f">Теперь имеются два PV (посмотреть можно через `pvs`):</mark>

```
/dev/sdc1
/dev/sdd1
```

### 8.4. Расширение группы VG

>[!INFO] <mark style="background:#fff88f">`vgextend`</mark>
><mark style="background:#fff88f">Команда добавления физического тома в существующую группу томов.</mark>

```bash
sudo vgextend vg_storage /dev/sdd1
```

<mark style="background:#fff88f">Проверим:</mark>

```bash
sudo vgs
```

<mark style="background:#fff88f">Объём группы увеличится примерно до 20 ГиБ. Однако логический том `lv_data` всё ещё имеет размер 5 ГиБ.</mark>

Добавление пространства в VG не означает автоматического увеличения существующих LV. Администратор сам определяет, как распределить новое пространство.

### .5. Расширение логического тома

`lvextend` — команда увеличения размера логического тома.

Увеличим `lv_data` на 8 ГиБ:
