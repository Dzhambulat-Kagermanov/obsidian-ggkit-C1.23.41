## Зачем вообще нужна маршрутизация? Проблема L2

Вспомним ключевое из коммутации:

- Коммутатор работает с **MAC-адресами** внутри **одного широковещательного домена** (broadcast domain, обычно = одна VLAN).
    
- Когда кадр приходит, коммутатор смотрит на MAC-адрес назначения и ищет его в **таблице MAC-адресов** (CAM-таблице).
    
- Если MAC неизвестен — кадр **флудится** во все порты, кроме входящего.
    

**Проблемы, которые L2 не решает:**

1. **Масштабирование.** Если объединить все устройства в один broadcast domain — получим огромный «шторм» широковещательных кадров (ARP, DHCP, NetBIOS). Коммутатор их все флудит.
    
2. **Изоляция.** Нет встроенного механизма ограничить, кто с кем может общаться.
    
3. **Связь между разными сетями.** Устройства в разных VLAN (или разных физических сетях) **не могут** общаться через коммутатор — MAC-адреса видны только внутри одного домена.
    

**Вывод:** нужен механизм, который соединит **разные L2-сети** и при этом будет принимать решения о пересылке **на основе логической адресации** (IP), а не MAC. Это и есть маршрутизация.

## Ключевая идея: что такое маршрутизация

**Маршрутизация** — это процесс выбора пути для пакета между **разными IP-сетями** и пересылка его через **маршрутизатор** (или L3-коммутатор).

Три ключевых отличия от коммутации:

| Аспект                | Коммутация (L2)       | Маршрутизация (L3)                     |
| --------------------- | --------------------- | -------------------------------------- |
| Адрес                 | MAC (flat, «плоский») | IP (иерархический)                     |
| Область               | Один broadcast domain | Между разными сетями                   |
| Решение о направлении | Таблица MAC           | Таблица маршрутизации                  |
| Кадр                  | Не меняется           | **Меняется** (перезапись L2-заголовка) |
| TTL                   | Нет                   | Есть, уменьшается на 1                 |

**Главное:** IP-адрес **иерархичен** — он состоит из части «сеть» + «хост». Это позволяет маршрутизаторам группировать миллионы адресов в один маршрут (префикс) и не хранить таблицу на каждый хост.

## Анатомия IP-адреса и подсети (без этого маршрутизация непонятна)

- **IP-адрес** = 32 бита (IPv4), например `192.168.1.10`.
- **Маска** отделяет сеть от хоста: `255.255.255.0` = `/24` → сеть `192.168.1.0/24`, хост `.10`.
- Устройства в **одной подсети** общаются напрямую (через L2, ARP).
- Устройства в **разных подсетях** — только через маршрутизатор.

**Префикс** (`/24`, `/16`, `/8`) — это и есть «маршрут» в таблице. Чем длиннее префикс, тем он **специфичнее**.

Пример: `10.0.0.0/8` — это 16 млн адре
