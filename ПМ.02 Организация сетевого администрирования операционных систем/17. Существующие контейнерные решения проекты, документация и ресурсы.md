## 1. Понятие контейнеризации

### 1.1. Что такое контейнер?

<mark style="background:#fff88f">**Контейнер** — изолированная среда выполнения приложения, использующая ядро операционной системы хоста и содержащая необходимые приложению файлы, библиотеки и зависимости.</mark>

<mark style="background:#fff88f">**Контейнеризация** — технология изоляции и запуска приложений в контейнерах без необходимости создавать отдельную полноценную виртуальную машину для каждого приложения.</mark>

Контейнер позволяет упаковать приложение вместе с его зависимостями и запускать его в разных совместимых окружениях. Например, веб-приложению нужны:

- Python определённой версии;
- набор библиотек;
- конфигурационные файлы;
- веб-сервер;
- переменные окружения.

### 1.2. Для чего нужна контейнеризация?

<mark style="background:#fff88f">Основные задачи контейнеризации:</mark>

1. <mark style="background:#fff88f">Изоляция приложений — процессы разных приложений работают в отдельных окружениях.</mark>
2. <mark style="background:#fff88f">Переносимость — один образ можно использовать на разных совместимых серверах.</mark>
3. <mark style="background:#fff88f">Упрощение развёртывания — приложение запускается с заранее подготовленными зависимостями.</mark>
4. <mark style="background:#fff88f">Воспроизводимость — одинаковая конфигурация образа помогает получать одинаковую среду выполнения.</mark>
5. <mark style="background:#fff88f">Эффективное использование ресурсов — контейнерам обычно не требуется отдельное ядро ОС.</mark>

Пример. На одном Linux-сервере необходимо запустить три веб-приложения, которым требуются разные версии Python. Контейнеризация позволяет предоставить каждому приложению собственное окружение, не устанавливая все версии и зависимости непосредственно в системную среду сервера.

## 2. Основные контейнерные решения

<mark style="background:#fff88f">Контейнерная экосистема включает разные классы программ: инструменты для запуска контейнеров, низкоуровневые runtime, системы управления контейнерами и платформы оркестрации.</mark>

### 2.1. Docker

![[images 1.png|151]]

<mark style="background:#fff88f">Docker — платформа для создания, распространения и запуска контейнерных приложений.</mark>

Основные компоненты:

- <mark style="background:#fff88f">Docker Engine — система управления контейнерами.</mark>
- <mark style="background:#fff88f">Docker CLI — интерфейс командной строки.</mark>
- <mark style="background:#fff88f">Dockerfile — файл инструкций для сборки образа.</mark>
- <mark style="background:#fff88f">Docker Compose — инструмент описания и запуска многоконтейнерных приложений.</mark>
- <mark style="background:#fff88f">Docker Hub — сайт на который загружаются образы контейнеров</mark>

### 2.2. Podman

![[images (1).png|161]]

<mark style="background:#fff88f">Podman — инструмент для создания, запуска и управления OCI-совместимыми контейнерами и группами контейнеров.</mark>

<mark style="background:#fff88f">В отличие от стандартной архитектуры Docker Engine, Podman не требует постоянно работающего центрального демона. Он также поддерживает запуск контейнеров без прав root.</mark>

### 2.3. Kubernetes

<mark style="background:#fff88f">Kubernetes — платформа оркестрации контейнерных приложений. Оркестрация контейнеров — автоматизированное управление размещением, запуском, масштабированием, сетевым взаимодействием и восстановлением контейнерных приложений.</mark>

<mark style="background:#fff88f">Пример: приложение работает в пяти экземплярах на трёх серверах. Если один сервер выходит из строя, Kubernetes может запланировать создание новых контейнеров на доступных серверах при наличии ресурсов.</mark>

## 3. Образ, контейнер и реестр образов

### 3.1. Контейнерный образ

<mark style="background:#fff88f">Контейнерный образ (Container Image) — набор файлов, метаданных и инструкций, необходимых для создания контейнера.</mark>

Образ может содержать:

- файлы приложения;
- библиотеки;
- исполняемые программы;
- настройки среды;
- информацию о команде запуска.

Контейнер — запущенный или созданный экземпляр образа со своим состоянием выполнения и записываемым слоем.

Один образ можно использовать для создания нескольких контейнеров.

>[!EXAMPLE] Аналогия
>Образ это чертеж, контейнер это дом который мы построили. Один чертеж можно использовать для постройки огромного числа домов



### 5.2. Реестр образов

Container Registry — сервис хранения и распространения контейнерных образов.

Примеры:

- Docker Hub;
    
- GitHub Container Registry;
    
- Quay.io;
    
- собственный корпоративный registry.
    

Repository — логическое хранилище образов определённого приложения внутри registry.

Tag — метка версии или варианта образа, например `nginx:stable`.

Digest — идентификатор содержимого образа на основе криптографического хеша. В отличие от тега, digest позволяет сослаться на конкретное содержимое.
