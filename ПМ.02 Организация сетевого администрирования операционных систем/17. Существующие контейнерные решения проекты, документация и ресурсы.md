## 1. Понятие контейнеризации

### 1.1. Что такое контейнер?

<mark style="background:#fff88f">**Контейнер** — изолированная среда выполнения приложения, использующая ядро операционной системы хоста и содержащая необходимые приложению файлы, библиотеки и зависимости.</mark>

<mark style="background:#fff88f">**Контейнеризация** — технология изоляции и запуска приложений в контейнерах без необходимости создавать отдельную полноценную виртуальную машину для каждого приложения.</mark>

Контейнер позволяет упаковать приложение вместе с его зависимостями и запускать его в разных совместимых окружениях. Например, веб-приложению нужны:

- Python определённой версии;
- набор библиотек;
- конфигурационные файлы;
- веб-сервер;
- переменные окружения.

### 1.2. Для чего нужна контейнеризация?

<mark style="background:#fff88f">Основные задачи контейнеризации:</mark>

1. <mark style="background:#fff88f">Изоляция приложений — процессы разных приложений работают в отдельных окружениях.</mark>
2. <mark style="background:#fff88f">Переносимость — один образ можно использовать на разных совместимых серверах.</mark>
3. <mark style="background:#fff88f">Упрощение развёртывания — приложение запускается с заранее подготовленными зависимостями.</mark>
4. <mark style="background:#fff88f">Воспроизводимость — одинаковая конфигурация образа помогает получать одинаковую среду выполнения.</mark>
5. <mark style="background:#fff88f">Эффективное использование ресурсов — контейнерам обычно не требуется отдельное ядро ОС.</mark>

Пример. На одном Linux-сервере необходимо запустить три веб-приложения, которым требуются разные версии Python. Контейнеризация позволяет предоставить каждому приложению собственное окружение, не устанавливая все версии и зависимости непосредственно в системную среду сервера.

## 2. Основные контейнерные решения

<mark style="background:#fff88f">Контейнерная экосистема включает разные классы программ: инструменты для запуска контейнеров, низкоуровневые runtime, системы управления контейнерами и платформы оркестрации.</mark>

### 2.1. Docker

<mark style="background:#fff88f">Docker — платформа для создания, распространения и запуска контейнерных приложений.</mark>

<mark style="background:#fff88f">Docker Engine использует клиент-серверную архитектуру: клиент `docker` взаимодействует с демоном `dockerd`, который управляет образами, контейнерами, сетями и томами.</mark>

Основные компоненты:

- Docker Engine — система управления контейнерами.
- Docker CLI — интерфейс командной строки.
- Dockerfile — файл инструкций для сборки образа.
- Docker Compose — инструмент описания и запуска многоконтейнерных приложений.
- Docker Hub — реестр контейнерных образов
