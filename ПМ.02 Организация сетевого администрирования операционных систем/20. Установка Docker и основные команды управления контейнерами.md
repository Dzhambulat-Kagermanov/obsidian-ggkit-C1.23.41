## 1. Установка Docker

<mark style="background:#fff88f">**Docker Engine** — программная платформа для создания и запуска контейнеров.</mark>

<mark style="background:#fff88f">Установка Docker:</mark>

```bash
sudo apt update
sudo apt install docker.io -y
```

<mark style="background:#fff88f">Проверка установленной версии:</mark>

```bash
docker --version
```

<mark style="background:#fff88f">Проверка работоспособности Docker:</mark>

```
sudo docker run --rm hello-world
```

<mark style="background:#fff88f">В консоль должно вывестить сообщение `Hello from Docker!`.</mark>

## 2. Управление образами

**Образ (Image)** — готовый набор файлов и настроек, на основе которого создаются контейнеры.

### 2.1. Загрузка образа

```
sudo docker pull nginx:stable
```

- `pull` — загрузка образа.
- `nginx` — название образа.
- `stable` — тег образа.

### 2.2. Просмотр образов

```
sudo docker images
```

Основные сведения: название, тег, идентификатор и размер образа.

### 2.3. Удаление образа

```
sudo docker rmi nginx:stable
```

`rmi` — удаление локального образа. Образ, используемый существующим контейнером, может быть недоступен для удаления.

## 3. Создание и запуск контейнеров

### 3.1. Создание и запуск контейнера

`**docker run**` — создание нового контейнера из образа с последующим запуском.

```
sudo docker run -d --name web -p 8080:80 nginx:stable
```

**Параметры запуска:**

|Параметр|Назначение|
|---|---|
|`-d`|Фоновый режим|
|`--name web`|Назначение имени контейнера|
|`-p 8080:80`|Публикация порта 80 контейнера через порт 8080 сервера|
|`nginx:stable`|Выбор образа|

**Проверка работы веб-сервера:**

```
curl http://localhost:8080
```

### 3.2. Интерактивный запуск

**Интерактивный режим** — запуск контейнера с возможностью ввода команд через терминал.

```
sudo docker run -it --name ubuntu-test ubuntu:24.04 bash
```

- `-i` — поддержка ввода.
    
- `-t` — выделение терминала.
    
- `bash` — запуск командной оболочки.
    

**Завершение работы:**

```
exit
```

После завершения основного процесса `bash` контейнер останавливается.

### 3.3. Автоматическое удаление контейнера

```
sudo docker run --rm hello-world
```

`--rm` — автоматическое удаление контейнера после завершения его работы.

## 4. Просмотр контейнеров

### 4.1. Просмотр запущенных контейнеров

```
sudo docker ps
```

### 4.2. Просмотр всех контейнеров

```
sudo docker ps -a
```

Отображение запущенных и остановленных контейнеров.

**Основные сведения:**

|Столбец|Назначение|
|---|---|
|`CONTAINER ID`|Идентификатор|
|`IMAGE`|Используемый образ|
|`STATUS`|Состояние|
|`PORTS`|Опубликованные порты|
|`NAMES`|Имя контейнера|

## 5. Управление состоянием контейнеров

Для примеров используется ранее созданный контейнер `web`.

### 5.1. Остановка контейнера

```
sudo docker stop web
```

`stop` — запрос корректного завершения работы контейнера.

### 5.2. Запуск остановленного контейнера

```
sudo docker start web
```

`start` — запуск существующего контейнера без повторного создания.

### 5.3. Перезапуск контейнера

```
sudo docker restart web
```

`restart` — остановка и повторный запуск контейнера.

### 5.4. Принудительное завершение

```
sudo docker kill web
```

`kill` — принудительное завершение основного процесса контейнера. По умолчанию используется сигнал `SIGKILL`.

> [!IMPORTANT]  
> `docker run` создаёт **новый контейнер**, а `docker start` запускает **существующий**.

## 6. Просмотр работы контейнера

Перед выполнением следующих команд — запуск контейнера:

```
sudo docker start web
```

### 6.1. Просмотр журналов

**Журналы (Logs)** — сообщения приложения, формируемые во время его работы.

```
sudo docker logs web
```

**Непрерывный просмотр новых сообщений:**

```
sudo docker logs -f web
```

Завершение просмотра — `Ctrl+C`.

### 6.2. Выполнение команд внутри контейнера

`**docker exec**` — выполнение дополнительной команды внутри работающего контейнера.

```
sudo docker exec web ls /usr/share/nginx/html
```

**Открытие командной оболочки:**

```
sudo docker exec -it web /bin/sh
```

Завершение оболочки — `exit`. Основной процесс контейнера продолжает работать.

### 6.3. Просмотр использования ресурсов

```
sudo docker stats
```

Отображение загрузки процессора, использования памяти и сетевого ввода-вывода.

### 6.4. Просмотр конфигурации контейнера

```
sudo docker inspect web
```

Вывод подробных технических сведений о контейнере в формате JSON.

## 7. Удаление контейнеров

### 7.1. Удаление остановленного контейнера

```
sudo docker stop web
sudo docker rm web
```

`rm` — удаление контейнера.

### 7.2. Принудительное удаление

```
sudo docker rm -f web
```

`-f` — принудительное удаление, в том числе работающего контейнера.

> [!WARNING]  
> При удалении контейнера удаляется его записываемый слой. Образ при этом обычно остаётся на сервере.

## 8. Автоматический перезапуск контейнеров

**Restart Policy** — правило автоматического перезапуска контейнера.

**Создание контейнера с автоматическим перезапуском:**

```
sudo docker run -d --name web-auto --restart unless-stopped nginx:stable
```

**Основные политики:**

|Политика|Назначение|
|---|---|
|`no`|Без автоматического перезапуска|
|`on-failure`|Перезапуск при завершении с ошибкой|
|`always`|Автоматический перезапуск с учётом правил ручной остановки|
|`unless-stopped`|Автоматический перезапуск, кроме вручную остановленных контейнеров|
