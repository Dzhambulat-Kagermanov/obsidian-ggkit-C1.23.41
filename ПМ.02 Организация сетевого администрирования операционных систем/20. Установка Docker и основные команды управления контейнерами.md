## 1. Установка Docker

### 1.1. Установка

<mark style="background:#fff88f">Установка Docker:</mark>

```bash
sudo apt update
sudo apt install docker.io -y
```

### 1.2. Проверка установки

<mark style="background:#fff88f">Проверка версии Docker:</mark>

```bash
docker --version
```

<mark style="background:#fff88f">Проверка работоспособности запуском тестового контейнера `hello world`:</mark>

```bash
sudo docker run hello-world
```

Docker загружает тестовый образ `hello-world`, создаёт контейнер и запускает его. После вывода сообщения `Hello from Docker!` контейнер завершает работу.

## 2. Работа с контейнерными образами

### 2.1. Понятие контейнерного образа

<mark style="background:#fff88f">**Контейнерный образ (Image)** — набор файлов, программ и настроек, необходимых для создания контейнера.</mark>

<mark style="background:#fff88f">Перед запуском приложения Docker должен получить его образ. Образ может находиться на локальном компьютере или в удалённом реестре, например Docker Hub.</mark>

<mark style="background:#fff88f">**Docker Hub** — сервис для хранения и распространения контейнерных образов.</mark>

### 2.2. Загрузка образа — `pull`

<mark style="background:#fff88f">`docker pull` — команда загрузки контейнерного образа из реестра.</mark>

```
sudo docker pull nginx
```

<mark style="background:#fff88f">В результате Docker загружает образ Nginx и сохраняет его локально.</mark>

<mark style="background:#fff88f">**Тег (Tag)** — метка, позволяющая выбрать определённую версию или вариант образа. Пример:</mark>

```
sudo docker pull nginx:stable
```

<mark style="background:#fff88f">При отсутствии тега Docker по умолчанию использует `latest`.</mark>

### **2.3. Просмотр образов —** `images`

<mark style="background:#fff88f">`docker images` — команда просмотра образов, сохранённых на сервере.</mark>

```
sudo docker images
```

Основные столбцы:

|Столбец|Назначение|
|---|---|
|`REPOSITORY`|Название образа|
|`TAG`|Тег|
|`IMAGE ID`|Идентификатор образа|
|`SIZE`|Размер образа|

## 3. Создание и запуск контейнеров

### **3.1. Команда** `docker run`

<mark style="background:#fff88f">`docker run` — команда создания и запуска нового контейнера на основе образа.</mark>

Общий синтаксис:

```
docker run ИМЯ_ОБРАЗА
```

Пример:

```
sudo docker run hello-world
```

Последовательность выполнения:

1. Поиск образа `hello-world` на сервере.
    
2. Загрузка образа из реестра при его отсутствии.
    
3. Создание контейнера.
    
4. Запуск основного процесса контейнера.
    
5. Завершение контейнера после окончания работы процесса.
    

**Основной процесс контейнера** — программа, запуск которой определяет время работы контейнера. При завершении основного процесса контейнер обычно переходит в остановленное состояние.

### **3.2. Запуск контейнера с Ubuntu**

Запуск контейнера:

```
sudo docker run ubuntu:24.04
```

В данном случае контейнер быстро завершает работу, поскольку в нём не запущен длительно работающий процесс.

Для взаимодействия с контейнером через терминал используется интерактивный режим.

### **3.3. Интерактивный режим —** `-it`

**Интерактивный режим** — запуск контейнера с возможностью вводить команды внутри него.

```
sudo docker run -it ubuntu:24.04 bash
```

Разбор:

- `-i` — сохранение возможности ввода команд.
    
- `-t` — создание терминала.
    
- `ubuntu:24.04` — используемый образ.
    
- `bash` — запускаемая командная оболочка.
    

После запуска появляется командная строка внутри контейнера.

Пример выполнения команды:

```
cat /etc/os-release
```

Выход из оболочки:

```
exit
```

После завершения `bash` контейнер останавливается.

### **3.4. Фоновый режим —** `-d`

**Фоновый режим (Detached Mode)** — запуск контейнера без постоянного подключения его вывода к терминалу.

Для запуска используется параметр `-d`.

Пример:

```
sudo docker run -d nginx
```

Контейнер запускает веб-сервер Nginx в фоновом режиме.

Терминал остаётся доступным для выполнения других команд.

**Отличие режимов:**

|Режим|Назначение|
|---|---|
|Обычный|Вывод приложения связан с терминалом|
|`-it`|Интерактивная работа внутри контейнера|
|`-d`|Работа контейнера в фоновом режиме|

### **3.5. Назначение имени —** `--name`

Docker автоматически назначает контейнерам случайные имена. Для удобства управления можно указать собственное имя.

```
sudo docker run -d --name web nginx
```

Разбор:

- `-d` — фоновый режим.
    
- `--name web` — назначение имени `web`.
    
- `nginx` — используемый образ.
    

Теперь для управления контейнером можно использовать имя `web` вместо его идентификатора.

> [!IMPORTANT]  
> Каждая команда `docker run` создаёт новый контейнер. Примеры с разными параметрами являются вариантами запуска, а не обязательной последовательностью команд.

## **4. Просмотр контейнеров**

### **4.1. Просмотр работающих контейнеров —** `ps`

`docker ps` — команда просмотра запущенных контейнеров.

```
sudo docker ps
```

Основные сведения:

|Столбец|Назначение|
|---|---|
|`CONTAINER ID`|Идентификатор контейнера|
|`IMAGE`|Используемый образ|
|`COMMAND`|Основная команда контейнера|
|`STATUS`|Текущее состояние|
|`NAMES`|Имя контейнера|

### **4.2. Просмотр всех контейнеров —** `ps -a`

```
sudo docker ps -a
```

Параметр `-a` позволяет отображать не только работающие, но и остановленные контейнеры.

**Основные состояния контейнеров:**

- `Created` — контейнер создан, но ещё не запущен.
    
- `Running` — контейнер работает.
    
- `Paused` — выполнение процессов приостановлено.
    
- `Exited` — основной процесс завершился.
    

## **5. Управление состоянием контейнеров**

Для следующих примеров используется контейнер с именем `web`.

### **5.1. Остановка —** `stop`

`docker stop` — команда корректной остановки работающего контейнера.

```
sudo docker stop web
```

Docker отправляет основному процессу сигнал завершения и предоставляет время для остановки. Если процесс не завершился, Docker может принудительно остановить его.

### **5.2. Запуск остановленного контейнера —** `start`

`docker start` — команда запуска ранее созданного контейнера.

```
sudo docker start web
```

В отличие от `docker run`, команда `start` не создаёт новый контейнер.

### **5.3. Перезапуск —** `restart`

`docker restart` — команда остановки и повторного запуска контейнера.

```
sudo docker restart web
```

Использование — перезапуск приложения без удаления контейнера.

### **5.4. Принудительное завершение —** `kill`

`docker kill` — команда отправки сигнала процессу контейнера. По умолчанию отправляется `SIGKILL`, вызывающий принудительное завершение.

```
sudo docker kill web
```

Отличие от `stop`:

- `stop` — попытка корректного завершения.
    
- `kill` — принудительное завершение по умолчанию.
    

### **5.5. Приостановка и возобновление —** `pause`**,** `unpause`

**Приостановка контейнера** — временная остановка выполнения его процессов без завершения.

```
sudo docker pause web
```

**Возобновление выполнения:**

```
sudo docker unpause web
```

Приостановленный контейнер сохраняет своё состояние в памяти.

## **6. Сетевой доступ к контейнерам**

### **6.1. Понятие сетевого порта**

**Сетевой порт** — числовой идентификатор, используемый для направления сетевых соединений определённому приложению.

Например:

- `80` — стандартный порт HTTP.
    
- `443` — стандартный порт HTTPS.
    
- `22` — стандартный порт SSH.
    

Веб-сервер Nginx внутри контейнера обычно принимает HTTP-соединения на порту `80`.

### **6.2. Почему контейнер недоступен через порт сервера**

По умолчанию Docker обычно подключает контейнер к отдельной виртуальной сети.

Контейнер получает собственное сетевое окружение, поэтому порт приложения внутри контейнера не становится автоматически доступным через IP-адрес хостового сервера.

Для доступа к приложению через хост используется публикация порта.

### **6.3. Публикация портов —** `-p`

**Публикация порта** — предоставление доступа к порту контейнера через указанный порт хостовой системы.

Синтаксис параметра:

```
-p ПОРТ_ХОСТА:ПОРТ_КОНТЕЙНЕРА
```

Пример:

```
-p 8080:80
```

Значение:

- `8080` — порт сервера с Docker.
    
- `80` — порт веб-сервера внутри контейнера.
    

При обращении к порту `8080` хоста соединение направляется на порт `80` контейнера.

### **6.4. Запуск Nginx с публикацией порта**

Для нового примера используется контейнер `web-http`:

```
sudo docker run -d -p 8080:80 nginx
```

Добавление имени контейнера:

```
sudo docker run -d --name web-http -p 8080:80 nginx
```

> [!NOTE]  
> Перед выполнением второго варианта необходимо удалить контейнер, созданный первой командой, либо сразу использовать второй вариант. Иначе порт `8080` уже может быть занят.

**Проверка доступности:**

```
curl http://localhost:8080
```

При успешном подключении отображается HTML-код стартовой страницы Nginx.

С другого компьютера обращение выполняется по адресу:

```
http://IP_СЕРВЕРА:8080
```

Доступность зависит от сетевых настроек и правил межсетевого экрана.

## **7. Диагностика и работа с контейнерами**

### **7.1. Просмотр журналов —** `logs`

**Журнал контейнера** — сообщения, которые приложение выводит в стандартные потоки вывода и ошибок и которые собирает настроенный механизм логирования Docker.

Просмотр журналов:

```
sudo docker logs web-http
```

**Непрерывный просмотр:**

```
sudo docker logs -f web-http
```

Параметр `-f` позволяет отображать новые сообщения по мере их появления.

**Просмотр последних 20 строк:**

```
sudo docker logs --tail 20 web-http
```

### **7.2. Выполнение команды внутри контейнера —** `exec`

`docker exec` — команда выполнения дополнительного процесса внутри работающего контейнера.

Пример просмотра файлов Nginx:

```
sudo docker exec web-http ls /usr/share/nginx/html
```

**Запуск интерактивной оболочки:**

```
sudo docker exec -it web-http /bin/sh
```

После запуска появляется возможность выполнять команды внутри контейнера.

Выход:

```
exit
```

При этом основной процесс Nginx продолжает работать.

### **7.3. Просмотр использования ресурсов —** `stats`

`docker stats` — команда отображения использования системных ресурсов контейнерами.

```
sudo docker stats
```

Отображаемые показатели:

- загрузка процессора;
    
- использование оперативной памяти;
    
- сетевой ввод-вывод;
    
- дисковый ввод-вывод;
    
- количество процессов.
    

### **7.4. Просмотр подробной информации —** `inspect`

`docker inspect` — команда получения подробных сведений о контейнере в формате JSON.

```
sudo docker inspect web-http
```

С помощью команды можно узнать параметры запуска, состояние, сетевые настройки и другую информацию.

## **8. Удаление контейнеров и образов**

### **8.1. Удаление контейнера —** `rm`

`docker rm` — команда удаления существующего контейнера.

Перед обычным удалением работающий контейнер необходимо остановить:

```
sudo docker stop web-http
```

Удаление:

```
sudo docker rm web-http
```

**Принудительное удаление:**

```
sudo docker rm -f web-http
```

Параметр `-f` позволяет принудительно удалить работающий контейнер.

### **8.2. Удаление образа —** `rmi`

`docker rmi` — команда удаления локального контейнерного образа.

```
sudo docker rmi nginx:stable
```

Если образ используется существующими контейнерами, Docker может запретить его удаление.

**Различие команд:**

|Команда|Объект удаления|
|---|---|
|`docker rm`|Контейнер|
|`docker rmi`|Образ|

## **9. Автоматический перезапуск контейнеров**

**Политика перезапуска (Restart Policy)** — настройка, определяющая условия автоматического запуска контейнера после завершения работы.

Для настройки используется параметр `--restart`.

Пример:

```
sudo docker run -d --restart unless-stopped nginx
```

**Основные политики:**

|Политика|Назначение|
|---|---|
|`no`|Отсутствие автоматического перезапуска|
|`on-failure`|Перезапуск при завершении с ошибкой|
|`always`|Автоматический перезапуск, кроме некоторых случаев ручной остановки до перезапуска демона|
|`unless-stopped`|Автоматический перезапуск, если контейнер не был остановлен вручную|

Политика `unless-stopped` удобна для сервисов, которые должны автоматически восстанавливать работу после перезагрузки сервера, но не должны запускаться после намеренной остановки администратором.
