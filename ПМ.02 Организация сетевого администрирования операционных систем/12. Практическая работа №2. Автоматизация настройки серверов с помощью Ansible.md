## Цель работы:

Научиться развёртывать управляющий узел Ansible, настраивать инвентарь и аутентификацию по SSH-ключам, выполнять ad-hoc команды и простые плейбуки, а также управлять состоянием управляемых узлов: перезагружать и выключать их.

## Задания

### Задание 1. Подготовка стенда и проверка доступа

**Цель:** Получить IP-адреса трёх виртуальных машин, убедиться, что на каждой есть Python 3, и проверить SSH-доступ с управляющего узла на управляемые.

1. Войдите во все три виртуальные машины (`control`, `managed-1`, `managed-2`) через консоль Proxmox.
2. Задайте название компьютера на всех трех вм.

**`oaks-practicheskaya-rabota-2-control`**

```bash
hostnamectl set-hostname control
exec bash
```

**`oaks-practicheskaya-rabota-2-managed-1`**

```bash
hostnamectl set-hostname managed-1
exec bash
```

**`oaks-practicheskaya-rabota-2-managed-2`**

```bash
hostnamectl set-hostname managed-2
exec bash
```

3. На всех машинах выполните команду для просмотра IP-адреса:

```bash
ip -c -br a
```

_(Запишите IP-адреса всех трёх машин. Допустим, это `192.168.1.40` для control, `192.168.1.41` для managed-1 и `192.168.1.42` для managed-2.)_

3. На всех трёх машинах проверьте версию Python:

```bash
python3 --version
```

4. На машине **control** попытайтесь подключиться к каждому управляемому узлу по паролю:

```bash
ssh user@<IP_managed-1>
```

_При первом подключении система выдаст предупреждение о невозможности проверить подлинность хоста. Введите `yes` и пароль `P@ssw0rd`. Затем выполните `exit`. Повторите то же самое для managed-2._

5. На машине **control** просмотрите содержимое файла доверенных хостов:

```bash
cat ~/.ssh/known_hosts
```

**Что отразить в отчёте:** Скриншоты IP-адресов трёх машин, вывод `python3 --version` на каждой машине, скриншот первого подключения с предупреждением и вывод `cat ~/.ssh/known_hosts`. Кратко объясните, зачем нужен файл `known_hosts` и почему управляющий узел должен подключиться к каждому управляемому хотя бы один раз.

### Задание 2. Установка Ansible на управляющем узле

**Цель:** Установить Ansible в виртуальное окружение Python на машине `control` и проверить его работу.

1. На машине **control** установите необходимые пакеты:

```bash
sudo apt update
sudo apt install python3 python3-pip python3-venv sshpass -y
```

_(Пакет `sshpass` нужен для входа по паролю, если вы не используете SSH-ключи.)_

2. Создайте рабочую папку и виртуальное окружение:

```bash
mkdir ~/ansible-workspace
cd ~/ansible-workspace
python3 -m venv venv
```

3. Активируйте окружение и установите Ansible:

```bash
source venv/bin/activate
pip install ansible
```

_(После активации в начале строки терминала появится `(venv)`.)_

4. Проверьте версию Ansible:

```bash
ansible --version
```

**Что отразить в отчёте:** Команды установки, скриншот вывода `ansible --version`. Объясните, зачем Ansible ставится в виртуальное окружение, а не в систему.

### Задание 3. Инвентарь, ansible.cfg и аутентификация по ключу

**Цель:** Создать файл инвентаризации с двумя управляемыми узлами, настроить вход по SSH-ключу и проверить связь командой `ping`.

1. На машине **control** сгенерируйте пару ключей Ed25519 (укажите свою фамилию-имя вместо **student**):

```bash
ssh-keygen -t ed25519 -C "student@lab.local" -f ~/.ssh/id_ed25519
```

_(Нажмите Enter, чтобы не устанавливать passphrase, так как это учебная среда.)_

2. Скопируйте публичный ключ на оба управляемых узла (потребуется ввести пароль один раз для каждого):

```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@<IP_managed-1>
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@<IP_managed-2>
```

3. Проверьте, что вход без пароля работает на обоих узлах:

```bash
ssh -i ~/.ssh/id_ed25519 user@<IP_managed-1>
exit
ssh -i ~/.ssh/id_ed25519 user@<IP_managed-2>
exit
```

4. В папке `~/ansible-workspace` создайте файл инвентаризации `inventory.ini`:

```ini
[managed]
managed-1 ansible_host=<IP_managed-1>
managed-2 ansible_host=<IP_managed-2>

[all:vars]
ansible_user=user
ansible_ssh_private_key_file=~/.ssh/id_ed25519
```

5. В той же папке создайте файл настроек `ansible.cfg`:

```ini
[defaults]
inventory = ./inventory.ini
host_key_checking = False
```

6. Проверьте, что инвентарь видит Ansible:

```bash
ansible-inventory --graph
```

7. Проверьте связь с управляемыми узлами:

```bash
ansible all -m ping
```

_(Ответ `pong` от каждого узла означает, что Ansible может подключиться и запустить Python.)_

**Что отразить в отчёте:** Скриншоты генерации ключа, успешного входа без пароля, содержимое `inventory.ini` и `ansible.cfg`, вывод `ansible-inventory --graph` и `ansible all -m ping`. Объясните, зачем нужна переменная `ansible_ssh_private_key_file` и что означает группа `managed`.

### Задание 4. Ad-hoc команды

**Цель:** Выполнять одиночные команды на управляемых узлах, в том числе с правами администратора.

1. Узнайте время работы системы на всех управляемых узлах:

```bash
ansible managed -m command -a "uptime"
```

2. Узнайте имя пользователя на каждом узле:

```bash
ansible managed -m command -a "whoami"
```

3. Установите пакет `htop` на оба управляемых узла. Для запуска `apt` нужны права администратора. Ключ `-b` включает повышение прав, ключ `-K` спросит пароль `sudo` (`P@ssw0rd`):

```bash
ansible managed -b -K -m apt -a "name=htop state=present update_cache=true"
```

4. Проверьте, что пакет установлен:

```bash
ansible managed -m command -a "htop --version"
```

5. Создайте файл на управляемых узлах с помощью модуля `copy`:

```bash
ansible managed -b -K -m copy -a "content='Файл создан через Ansible' dest=/tmp/ansible_test.txt"
```

6. Проверьте содержимое файла:

```bash
ansible managed -m command -a "cat /tmp/ansible_test.txt"
```

**Что отразить в отчёте:** Команды и вывод каждой команды. Для шага 3 объясните, зачем нужен ключ `-b` и почему для установки пакета нужен пароль `sudo`. Для шага 5 объясните разницу между модулями `command` и `copy`.

### Задание 5. Плейбуки: перезагрузка и выключение

**Цель:** Написать два простых плейбука: один перезагружает управляемые узлы, второй выключает их. Проверить результат каждого действия.

1. В папке `~/ansible-workspace` создайте плейбук `reboot.yml`:

```yaml
---
- name: Перезагрузка управляемых узлов
  hosts: managed
  become: true

  tasks:
    - name: Перезагрузить узел
      ansible.builtin.reboot:
        msg: "Перезагрузка через Ansible"
        reboot_timeout: 300
```

2. Запомните время работы системы до перезагрузки:

```bash
ansible managed -m command -a "uptime"
```

3. Запустите плейбук `reboot.yml`:

```bash
ansible-playbook reboot.yml -K
```

4. Проверьте, что узлы перезагрузились. Команда `uptime` должна показать небольшое время работы:

```bash
ansible managed -m command -a "uptime"
```

5. В папке `~/ansible-workspace` создайте плейбук `shutdown.yml`:

```yaml
---
- name: Выключение управляемых узлов
  hosts: managed
  become: true

  tasks:
    - name: Запланировать выключение через 1 минуту
      ansible.builtin.command: shutdown -h +1 "Выключение через Ansible"
```

6. Запустите плейбук `shutdown.yml`:

```bash
ansible-playbook shutdown.yml -K
```

7. Подождите около двух минут и проверьте связь с узлами:

```bash
ansible managed -m ping
```

_(Узлы должны стать недоступны: ответ `UNREACHABLE`. Это значит, что машины выключились.)_

8. Включите виртуальные машины `managed-1` и `managed-2` через Proxmox и убедитесь, что они снова отвечают на `ping`.

**Что отразить в отчёте:** Содержимое `reboot.yml` и `shutdown.yml`. Вывод `uptime` до и после перезагрузки, вывод `ansible-playbook` для обоих плейбуков с блоком `PLAY RECAP`, вывод `ping` после выключения, скриншот выключенных машин в Proxmox. Объясните, почему для перезагрузки используется модуль `reboot`, а для выключения — команда `shutdown` с задержкой в одну минуту.
