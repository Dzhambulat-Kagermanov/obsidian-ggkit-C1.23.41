# Введение в Ansible и формат YAML

> Конспект для студентов. Тема: система управления конфигурацией Ansible и язык YAML.

---

## 1. Что такое управление конфигурацией

**Конфигурация** — это настройки сервера или программы: какие пакеты установлены, какие службы запущены, какие файлы лежат в нужных местах.

**Управление конфигурацией** — это способ задавать эти настройки описанием в файле и автоматически применять их на одном или многих серверах.

Зачем это нужно:
- не нужно вручную заходить на каждый сервер и повторять одни и те же команды;
- одинаковая настройка на всех серверах;
- понятно, что и когда было изменено (описание хранится в файлах и в системе контроля версий, например Git);
- можно повторно запускать одно и то же описание — результат будет тот же.

---

## 2. Что такое Ansible

**Ansible** — инструмент управления конфигурацией с открытым исходным кодом.

Основные особенности:
- **Без агентов.** На управляемых серверах не нужно ставить никакое дополнительное ПО. Нужны только SSH-доступ и Python.
- **Описание в YAML.** Все задачи записываются в файлы формата YAML.
- **Идемпотентность.** Если нужное состояние уже достигнуто, Ansible ничего не меняет. Повторный запуск безопасен.
- **Управление с одной машины.** Команды отдаются с управляющего узла (control node), а выполняются на управляемых узлах (managed nodes).

---

## 3. Основные понятия

| Понятие | Что это |
|---|---|
| **Control node** | Машина, с которой запускается Ansible |
| **Managed node** | Сервер, которым управляет Ansible |
| **Inventory (инвентарь)** | Список серверов и их группы |
| **Module (модуль)** | Готовое действие: установить пакет, создать файл, запустить службу |
| **Task (задача)** | Одно действие, которое вызывает модуль |
| **Playbook (плейбук)** | Файл с набором задач для групп серверов |
| **Role (роль)** | Готовый набор задач, переменных и файлов для одной цели; используется для организации больших проектов |

## 4. Формат YAML

**YAML** — текстовый формат для описания данных. Файлы Ansible пишутся в нём.

Расширение файла: `.yml` или `.yaml`.

### 4.1. Главное правило: отступы

В YAML структура задаётся **отступами**, а не скобками.
- Отступы делаются **пробелами**. Табуляция запрещена.
- Обычно используется отступ в **2 пробела**.
- Вложенные элементы пишутся с большим отступом.

### 4.2. Пара «ключ: значение»

```yaml
имя: Иван
возраст: 20
город: Москва
```

- Ключ отделяется от значения **двоеточием и пробелом** (`: `).
- Значение можно не брать в кавычки, если оно простое.

### 4.3. Вложенные структуры (словари)

```yaml
студент:
  имя: Иван
  курс: 2
  предметы:
    математика: 5
    физика: 4
```

### 4.4. Списки

Элементы списка начинаются с дефиса и пробела (`- `).

```yaml
пакеты:
  - nginx
  - git
  - curl
```

Список внутри списка словарей:

```yaml
студенты:
  - имя: Иван
    курс: 2
  - имя: Мария
    курс: 3
```

### 4.5. Типы данных

```yaml
строка: "привет"          # кавычки необязательны, но допустимы
число: 42
дробное: 3.14
да_нет: true              # логический тип: true или false
пусто: null               # отсутствие значения
```

### 4.6. Комментарии

Комментарий начинается с символа `#`. Всё после него игнорируется.

```yaml
порт: 80   # это комментарий
```

### 4.7. Начало документа

Три дефиса в начале файла означают начало документа. Часто их ставят в плейбуках:

```yaml
---
имя: пример
```

### 4.8. Частые ошибки

- **Табуляция вместо пробелов.** YAML её не понимает.
- **Неверные отступы.** Элементы одного уровня должны начинаться с одной колонки.
- **Нет пробела после двоеточия.** Пишите `ключ: значение`, а не `ключ:значение`.
- **Нет пробела после дефиса.** Пишите `- элемент`, а не `-элемент`.
- **Спецсимволы в значениях.** Если значение содержит `:` или `#`, его лучше взять в кавычки.

## 5. Инвентарь (inventory)

Инвентарь — список серверов. Его можно записать в формате YAML.

```yaml
all:
  children:
    webservers:
      hosts:
        web1:
          ansible_host: 192.168.1.10
        web2:
          ansible_host: 192.168.1.11
    dbservers:
      hosts:
        db1:
          ansible_host: 192.168.1.20
```

- `all` — все серверы.
- `webservers` и `dbservers` — группы.
- `web1`, `web2`, `db1` — имена серверов.
- `ansible_host` — реальный IP-адрес или имя узла.

---

## 6. Плейбук (playbook)

Плейбук — основной файл Ansible. Это список **сценариев** (plays), каждый из которых применяется к группе серверов и содержит **задачи**.

Пример:

```yaml
---
- name: Установка веб-сервера
  hosts: webservers
  become: true

  tasks:
    - name: Установить nginx
      ansible.builtin.apt:
        name: nginx
        state: present

    - name: Запустить nginx
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true
```

Разбор:
- `name` — понятное описание. Не влияет на работу, нужно для чтения.
- `hosts` — на какие серверы (группы) действует сценарий.
- `become: true` — выполнять задачи с правами администратора (sudo).
- `tasks` — список задач.
- `ansible.builtin.apt` — модуль, который работает с пакетами в Debian/Ubuntu.
- `state: present` — пакет должен быть установлен. `state: absent` — удалён.
- `ansible.builtin.service` — модуль для управления службами.
- `state: started` — служба должна быть запущена.
- `enabled: true` — служба стартует вместе с системой.

## 7. Основные команды

Проверка связи с серверами:

```bash
ansible all -i inventory.yml -m ping
```

Запуск плейбука:

```bash
ansible-playbook -i inventory.yml site.yml
```

Проверка без реальных изменений (dry run):

```bash
ansible-playbook -i inventory.yml site.yml --check
```

Ключи:
- `-i` — указать файл инвентаря;
- `-m` — указать модуль;
- `--check` — только показать, что было бы изменено.

---

## 8. Главное в двух словах

- Ansible задаёт настройки серверов **описанием в файлах**, без установки агентов.
- Всё описывается в **YAML**: отступы пробелами, пары `ключ: значение`, списки через `- `.
- **Инвентарь** — список серверов, **плейбук** — список задач, **модуль** — готовое действие.
- Повторный запуск не ломает систему: Ansible меняет только то, что отличается от описания.
