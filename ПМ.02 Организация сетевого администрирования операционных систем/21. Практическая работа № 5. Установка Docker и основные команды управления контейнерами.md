# Задания

## Задание 1. Подготовка ВМ и установка Docker

**Цель:** установить Docker и проверить его работоспособность.

1. В Proxmox создайте полный клон шаблона `students-ubuntu26.04-template` с именем `oaks-practicheskaya-rabota-5`.
2. Запустите ВМ и войдите с логином `user` и паролем `P@ssw0rd`.
3. Проверьте IP-адрес ВМ.
4. Установите Docker из репозитория Ubuntu.
5. Проверьте версию Docker и запустите тестовый контейнер `hello-world`.

**Выполнение:**

Проверка сетевого адреса:

```bash
ip -c -br a
```

Установка Docker:

```bash
sudo apt update
sudo apt install docker.io -y
```

Проверка версии и запуск теста:

```bash
docker --version
sudo docker run hello-world
```

Контейнер `hello-world` выводит сообщение `Hello from Docker!` и завершает работу. Это нормальное поведение тестового контейнера.

**В отчёт:** скриншот ВМ в Proxmox, IP-адрес, версия Docker и результат `hello-world`.

## Задание 2. Загрузка образов и создание контейнеров

**Цель:** освоить работу с образами и различать интерактивный и фоновый режимы запуска.

1. Загрузите образы `nginx:stable` и `ubuntu:24.04`.
2. Просмотрите список локальных образов.
3. Запустите Ubuntu в интерактивном режиме, проверьте версию системы и завершите оболочку.
4. Запустите Nginx в фоновом режиме с именем `web`.
5. Просмотрите работающие и все созданные контейнеры.

**Выполнение:**

Загрузка образов:

```bash
sudo docker pull nginx:stable
sudo docker pull ubuntu:24.04
sudo docker images
```

Интерактивный запуск Ubuntu:

```bash
sudo docker run -it ubuntu:24.04 bash
```

**Внутри контейнера** выполните:

```bash
cat /etc/os-release
exit
```

После `exit` контейнер Ubuntu остановится, поскольку завершилась его основная оболочка `bash`.

Запуск Nginx в фоновом режиме:

```bash
sudo docker run -d --name web nginx:stable
sudo docker ps
sudo docker ps -a
```

Параметр `-d` запускает контейнер в фоне, а `--name web` задаёт его имя. Обратите внимание: каждая команда `docker run` создаёт **новый** контейнер.

**В отчёт:** список образов, результат просмотра версии Ubuntu, списки работающих и всех контейнеров. Объясните разницу между `docker images`, `docker ps` и `docker ps -a`.

## Задание 3. Управление состоянием контейнера

**Цель:** научиться останавливать, запускать и перезапускать существующий контейнер.

1. Остановите контейнер `web`.
2. Убедитесь, что он отсутствует в списке работающих, но присутствует среди всех контейнеров.
3. Запустите его повторно без создания нового контейнера.
4. Перезапустите контейнер.
5. Принудительно завершите его и проверьте состояние.

**Выполнение:**

Остановка и проверка:

```bash
sudo docker stop web
sudo docker ps
sudo docker ps -a
```

Повторный запуск и перезапуск:

```bash
sudo docker start web
sudo docker restart web
sudo docker ps
```

Принудительное завершение:

```bash
sudo docker kill web
sudo docker ps -a
```

`docker start` запускает уже созданный контейнер, `docker restart` перезапускает его, а `docker kill` принудительно завершает основной процесс контейнера.

**В отчёт:** команды и состояния контейнера после остановки, запуска, перезапуска и принудительного завершения. Объясните разницу между `run` и `start`.

## Задание 4. Проброс порта и проверка веб-сервера

**Цель:** предоставить доступ к веб-серверу внутри контейнера через порт виртуальной машины.

1. Создайте новый контейнер `web-http` на основе `nginx:stable`.
2. Опубликуйте порт контейнера `80` на порту ВМ `8080`.
3. Проверьте, что контейнер запущен.
4. Проверьте доступность веб-сервера из терминала ВМ.
5. Определите IP-адрес ВМ и откройте веб-страницу с компьютера, имеющего доступ к лабораторной сети.

**Выполнение:**

```bash
sudo docker run -d --name web-http -p 8080:80 nginx:stable
sudo docker ps
```

В записи `-p 8080:80` число `8080` — порт ВМ, а `80` — порт Nginx внутри контейнера.

Проверка из терминала ВМ:

```bash
curl http://127.0.0.1:8080
```

Если команда `curl` отсутствует, установите её:

```bash
sudo apt install curl -y
```

Просмотр IP-адреса:

```bash
ip -c -br a
```

В браузере откройте:

```text
http://<IP_ВМ>:8080
```

Вместо `<IP_ВМ>` укажите настоящий IPv4-адрес ВМ. Должна появиться стандартная страница Nginx. Если браузер не может подключиться, достаточно подтвердить работу локальным запросом `curl` и проверить сетевую доступность ВМ.

**В отчёт:** результат `docker ps`, вывод `curl` и скриншот страницы Nginx (если доступна). Объясните назначение `-p 8080:80`.

## Задание 5. Диагностика и изучение контейнера

**Цель:** просмотреть журналы, выполнить команду внутри контейнера и изучить его параметры и потребление ресурсов.

1. Просмотрите журнал контейнера `web-http`.
2. Откройте потоковый просмотр журнала и сформируйте новый запрос к Nginx.
3. Выполните команду просмотра файлов внутри работающего контейнера.
4. Просмотрите статистику использования ресурсов.
5. Получите подробную информацию о контейнере.

**Выполнение:**

Просмотр журнала:

```bash
sudo docker logs web-http
```

Для просмотра новых сообщений:

```bash
sudo docker logs -f web-http
```

Оставьте просмотр журнала открытым. Из другого терминала или браузера обратитесь к `http://<IP_ВМ>:8080`. Убедитесь, что появилась новая запись. Остановите просмотр сочетанием `Ctrl+C` — **сам контейнер при этом продолжит работать**.

Выполнение команды внутри контейнера:

```bash
sudo docker exec web-http ls /usr/share/nginx/html
```

Просмотр статистики:

```bash
sudo docker stats
```

Для выхода из непрерывного просмотра нажмите `Ctrl+C`.

Подробные сведения:

```bash
sudo docker inspect web-http
```

**В отчёт:** журнал после обращения к веб-серверу, вывод `exec`, скриншот `stats`, фрагмент `inspect` с информацией о состоянии или сетевых настройках. Объясните назначение каждой команды.

## Задание 6. Политика перезапуска и удаление ресурсов

**Цель:** настроить автоматический запуск контейнера и удалить ненужные контейнеры и образы.

1. Создайте контейнер `web-auto` с политикой `unless-stopped`.
2. Проверьте, что контейнер запущен, и посмотрите его политику перезапуска.
3. Перезапустите виртуальную машину и проверьте, что `web-auto` снова работает.
4. Остановите и удалите учебные контейнеры `web`, `web-http` и `web-auto`.
5. Удалите образ `nginx:stable` и проверьте список оставшихся образов.

**Выполнение:**

Создание контейнера с политикой перезапуска:

```bash
sudo docker run -d --name web-auto --restart unless-stopped nginx:stable
sudo docker ps
sudo docker inspect -f '{{.HostConfig.RestartPolicy.Name}}' web-auto
```

Ожидаемое значение политики — `unless-stopped`.

Перезагрузка ВМ:

```bash
sudo reboot
```

После повторного входа:

```bash
sudo docker ps
```

Контейнер `web-auto` должен автоматически запуститься. Для его работы не требуется публиковать порт.

Удаление контейнеров:

```bash
sudo docker stop web-http web-auto
sudo docker rm web web-http web-auto
sudo docker ps -a
```

Если остались остановленные контейнеры Ubuntu и `hello-world`, их можно оставить: они не мешают удалению образа Nginx.

Удаление образа Nginx:

```bash
sudo docker rmi nginx:stable
sudo docker images
```

**В отчёт:** политика `unless-stopped`, список контейнеров после перезагрузки, команды удаления и итоговый список образов. Объясните разницу между `docker rm` и `docker rmi`.
