# Задания

## Задание 1. Подготовка ВМ, установка Docker и настройка Harbor Proxy

**Цель:** установить Docker, настроить подключение к Harbor Proxy и проверить работоспособность.

1. В Proxmox создайте полный клон шаблона `students-ubuntu26.04-template` с именем `oaks-practicheskaya-rabota-5`.
2. Запустите ВМ и войдите с логином `user` и паролем `P@ssw0rd`.
3. Проверьте IP-адрес ВМ.
4. Установите Docker из репозитория Ubuntu.
5. Настройте Docker для загрузки образов с `harbor.ggkit.local:8082` и перезапустите службу.
6. Проверьте версию Docker и загрузите образ игры Snake.

**Выполнение:**

Проверка сетевого адреса:

```bash
ip -c -br a
```

Установка Docker:

```bash
sudo apt update
sudo apt install docker.io -y
```

Настройка Harbor Proxy (используется HTTP-реестр, поэтому требуется разрешение `insecure-registries`):

```bash
sudo nano /etc/docker/daemon.json
```

Содержимое файла:

```json
{
  "insecure-registries": ["harbor.ggkit.local:8082"]
}
```

Сохранение: `Ctrl+O`, `Enter`, `Ctrl+X`.

Применение настроек:

```bash
sudo systemctl restart docker
```

Проверка Docker и загрузка первой игры:

```bash
docker --version
sudo docker pull harbor.ggkit.local:8082/docker-hub-proxy/sidhu1504/snake-game:latest
sudo docker images
```

**Важно:** настройка `insecure-registries` разрешает Docker подключаться к указанному реестру без проверки защищённого HTTPS-соединения. Использовать только для указанного учебного Harbor Proxy.

**В отчёт:** скриншот ВМ в Proxmox, IP-адрес, версия Docker, содержимое `daemon.json` и результат загрузки образа Snake.

## Задание 2. Загрузка образов и создание игровых контейнеров

**Цель:** освоить загрузку образов и запуск контейнеров в фоновом режиме.

1. Загрузите образ игры 2048 через Harbor Proxy.
2. Просмотрите список локальных образов.
3. Запустите игру Snake в контейнере `game-snake` с портом ВМ `5000`.
4. Запустите игру 2048 в контейнере `game-2048` с портом ВМ `8080`.
5. Просмотрите работающие и все созданные контейнеры.

**Выполнение:**

Загрузка образа 2048:

```bash
sudo docker pull harbor.ggkit.local:8082/docker-hub-proxy/aashiqq/2048-game:latest
sudo docker images
```

Запуск Snake:

```bash
sudo docker run -d --name game-snake -p 5000:5000 harbor.ggkit.local:8082/docker-hub-proxy/sidhu1504/snake-game:latest
```

Запуск 2048:

```bash
sudo docker run -d --name game-2048 -p 8080:80 harbor.ggkit.local:8082/docker-hub-proxy/aashiqq/2048-game:latest
```

Проверка контейнеров:

```bash
sudo docker ps
sudo docker ps -a
```

Параметр `-d` запускает контейнер в фоне, `--name` задаёт его имя, а `-p` публикует порт. Каждая команда `docker run` создаёт **новый** контейнер.

**В отчёт:** список образов, списки работающих и всех контейнеров. Объясните разницу между `docker images`, `docker ps` и `docker ps -a`.

## Задание 3. Управление состоянием контейнера

**Цель:** научиться останавливать, запускать и перезапускать существующий игровой контейнер.

1. Остановите контейнер `game-snake`.
2. Убедитесь, что он отсутствует среди работающих, но присутствует среди всех контейнеров.
3. Запустите его повторно без создания нового контейнера.
4. Перезапустите контейнер.
5. Принудительно завершите его, проверьте состояние и снова запустите.

**Выполнение:**

Остановка и проверка:

```bash
sudo docker stop game-snake
sudo docker ps
sudo docker ps -a
```

Повторный запуск и перезапуск:

```bash
sudo docker start game-snake
sudo docker restart game-snake
sudo docker ps
```

Принудительное завершение и восстановление:

```bash
sudo docker kill game-snake
sudo docker ps -a
sudo docker start game-snake
```

`docker start` запускает существующий контейнер, `docker restart` перезапускает его, а `docker kill` принудительно завершает основной процесс.

**В отчёт:** команды и состояния контейнера после остановки, запуска, перезапуска и принудительного завершения. Объясните разницу между `run` и `start`.

## Задание 4. Проброс портов и проверка игр в браузере

**Цель:** проверить доступ к играм через сетевые порты виртуальной машины.

1. Проверьте, что оба контейнера запущены.
2. Определите IP-адрес ВМ.
3. Проверьте доступность игр из терминала ВМ.
4. Откройте обе игры в браузере компьютера, имеющего доступ к лабораторной сети.
5. Объясните, какие порты принадлежат ВМ, а какие — контейнерам.

**Выполнение:**

```bash
sudo docker ps
ip -c -br a
```

Проверка HTTP-ответа:

```bash
curl -I http://127.0.0.1:5000
curl -I http://127.0.0.1:8080
```

Если `curl` отсутствует:

```bash
sudo apt install curl -y
```

Откройте в браузере:

- **Snake:** `http://<IP_ВМ>:5000`
- **2048:** `http://<IP_ВМ>:8080`

Вместо `<IP_ВМ>` укажите настоящий IPv4-адрес ВМ. Для Snake используется `-p 5000:5000`, для 2048 — `-p 8080:80`. Число **слева** — порт ВМ, **справа** — порт внутри контейнера.

Если браузер не может подключиться, проверьте доступность ВМ по сети и результаты локальных запросов `curl`.

**В отчёт:** результат `docker ps`, результаты `curl` и скриншоты обеих игр в браузере. Объясните назначение `-p 8080:80` и `-p 5000:5000`.

## Задание 5. Диагностика и изучение контейнера

**Цель:** просмотреть журналы, выполнить команду внутри контейнера и изучить его параметры и потребление ресурсов.

1. Просмотрите журнал контейнера `game-2048`.
2. Откройте потоковый просмотр журнала и обратитесь к игре через браузер.
3. Выполните команду внутри работающего контейнера.
4. Просмотрите статистику использования ресурсов.
5. Получите подробную информацию о контейнере.

**Выполнение:**

Просмотр журнала:

```bash
sudo docker logs game-2048
```

Потоковый просмотр:

```bash
sudo docker logs -f game-2048
```

Откройте `http://<IP_ВМ>:8080` в браузере и проверьте, появились ли новые записи. Наличие записей зависит от настройки приложения. Для выхода нажмите `Ctrl+C` — сам контейнер продолжит работать.

Выполнение команды внутри контейнера:

```bash
sudo docker exec game-2048 ls /
```

Просмотр статистики:

```bash
sudo docker stats
```

Для выхода нажмите `Ctrl+C`.

Подробные сведения:

```bash
sudo docker inspect game-2048
```

**В отчёт:** журнал, вывод `exec`, скриншот `stats`, фрагмент `inspect` с информацией о состоянии или сетевых настройках. Объясните назначение каждой команды.

## Задание 6. Политика перезапуска и удаление ресурсов

**Цель:** настроить автоматический запуск игрового контейнера и удалить ненужные контейнеры и образы.

1. Создайте ещё один контейнер с игрой 2048 под именем `game-auto` и политикой `unless-stopped`.
2. Используйте порт ВМ `8081`, чтобы не занять порт уже работающей игры.
3. Проверьте политику перезапуска.
4. Перезагрузите ВМ и убедитесь, что `game-auto` работает.
5. Остановите и удалите учебные контейнеры, затем удалите оба игровых образа.

**Выполнение:**

Создание контейнера:

```bash
sudo docker run -d --name game-auto --restart unless-stopped -p 8081:80 harbor.ggkit.local:8082/docker-hub-proxy/aashiqq/2048-game:latest
sudo docker ps
```

Проверка политики:

```bash
sudo docker inspect -f '{{.HostConfig.RestartPolicy.Name}}' game-auto
```

Перезагрузка ВМ:

```bash
sudo reboot
```

После повторного входа:

```bash
sudo docker ps
```

Контейнер `game-auto` должен запуститься автоматически. Дополнительная игра доступна по адресу `http://<IP_ВМ>:8081`.

Остановка и удаление контейнеров:

```bash
sudo docker stop game-snake game-2048 game-auto
sudo docker rm game-snake game-2048 game-auto
sudo docker ps -a
```

Удаление игровых образов:

```bash
sudo docker rmi harbor.ggkit.local:8082/docker-hub-proxy/sidhu1504/snake-game:latest
sudo docker rmi harbor.ggkit.local:8082/docker-hub-proxy/aashiqq/2048-game:latest
sudo docker images
```

**В отчёт:** значение политики `unless-stopped`, список контейнеров после перезагрузки, команды удаления и итоговый список образов. Объясните разницу между `docker rm` и `docker rmi`.
