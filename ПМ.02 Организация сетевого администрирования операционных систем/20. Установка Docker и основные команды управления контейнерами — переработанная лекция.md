# Установка Docker и основные команды управления контейнерами

## 1. Установка Docker

<mark style="background:#fff88f">**Docker Engine** — программа, которая создаёт и запускает контейнеры. Управление выполняется командой `docker`.</mark>

<mark style="background:#fff88f">Установка Docker:</mark>

```bash
sudo apt update
sudo apt install -y docker.io
```

<mark style="background:#fff88f">Проверка установленную версию:</mark>

```bash
docker --version
```

Проверим работу Docker запуском тестового контейнера:

```bash
sudo docker run --rm hello-world
```

Если появилось сообщение `Hello from Docker!`, установка работает.

## 2. Работа с образами

**Образ** — готовый набор файлов и настроек, из которого создаётся контейнер.

### 2.1. Скачать образ — `pull`

```bash
sudo docker pull nginx:latest
```

Команда загружает образ Nginx с тегом `latest`. Если образ отсутствует при запуске контейнера, Docker обычно загружает его автоматически.

### 2.2. Посмотреть образы — `images`

```bash
sudo docker images
```

В результате отображаются скачанные ранее образы

### 2.3. Удалить образ — `rmi`

```bash
sudo docker rmi nginx:latest
```

Команда удаляет локальную ссылку на образ. Если образ используется существующим контейнером, Docker может запретить удаление.

## 3. Создание и запуск контейнеров

### 3.1. Запуск — `run`

**`docker run`** — создаёт новый контейнер из образа и запускает его.

```bash
sudo docker run -d --name web -p 8080:80 nginx:stable
```

| Часть команды | Значение |
|---|---|
| `run` | Создать и запустить контейнер |
| `-d` | Работать в фоновом режиме |
| `--name web` | Назвать контейнер `web` |
| `-p 8080:80` | Направлять обращения к порту 8080 сервера на порт 80 контейнера |
| `nginx:stable` | Использовать образ Nginx |

Проверим работу веб-сервера:

```bash
curl http://localhost:8080
```

При обращении с другого компьютера используется IP-адрес сервера: `http://IP_СЕРВЕРА:8080` (если доступ не заблокирован сетевыми правилами).

> [!IMPORTANT] Команда `run` **каждый раз создаёт новый контейнер**. Чтобы запустить ранее остановленный контейнер, используется `start`.

### 3.2. Запуск в интерактивном режиме — `-it`

```bash
sudo docker run -it --name test-ubuntu ubuntu:24.04 bash
```

- `-i` — позволяет вводить команды с клавиатуры.
- `-t` — создаёт терминал.
- `bash` — запускает командную оболочку внутри контейнера.

Для выхода из оболочки:

```bash
exit
```

После выхода контейнер остановится, поскольку завершился его основной процесс `bash`.

### 3.3. Временный контейнер — `--rm`

```bash
sudo docker run --rm hello-world
```

`--rm` автоматически удаляет контейнер после завершения его работы. Удобно для коротких тестов.

## 4. Просмотр контейнеров

### 4.1. Запущенные контейнеры — `ps`

```bash
sudo docker ps
```

### 4.2. Все контейнеры — `ps -a`

```bash
sudo docker ps -a
```

Отображаются и запущенные, и остановленные контейнеры.

Основные столбцы:

| Столбец | Значение |
|---|---|
| `CONTAINER ID` | Идентификатор контейнера |
| `IMAGE` | Образ |
| `STATUS` | Состояние контейнера |
| `PORTS` | Опубликованные порты |
| `NAMES` | Имя контейнера |

Для управления можно использовать **имя** контейнера или его **ID**.

## 5. Остановка, запуск и перезапуск

Для следующих примеров используется контейнер `web`, созданный в разделе 3.

### 5.1. Остановить — `stop`

```bash
sudo docker stop web
```

Docker запрашивает корректное завершение основного процесса контейнера. Если тот не завершится вовремя, Docker принудительно остановит его.

### 5.2. Запустить остановленный — `start`

```bash
sudo docker start web
```

Контейнер запускается повторно **без создания нового контейнера**.

### 5.3. Перезапустить — `restart`

```bash
sudo docker restart web
```

Команда останавливает и снова запускает тот же контейнер.

### 5.4. Принудительно завершить — `kill`

```bash
sudo docker kill web
```

По умолчанию отправляет сигнал `SIGKILL`, не предоставляя приложению времени на корректное завершение. Используется, когда обычная остановка не помогает.

| Команда | Действие |
|---|---|
| `run` | Создать **новый** контейнер и запустить |
| `stop` | Остановить существующий |
| `start` | Запустить остановленный |
| `restart` | Перезапустить существующий |
| `kill` | Принудительно завершить |

## 6. Удаление контейнеров

**`docker rm`** — удаляет контейнер. Обычно сначала нужно его остановить.

```bash
sudo docker stop web
sudo docker rm web
```

Для принудительного удаления запущенного контейнера:

```bash
sudo docker rm -f web
```

> [!WARNING] Удаление контейнера удаляет его записываемый слой. Важные данные, которые нужно сохранять независимо от контейнера, размещают в томах (Docker Volumes); они будут разобраны в следующей лекции.

**После удаления контейнера его образ обычно остаётся на сервере.**

## 7. Просмотр работы контейнера

Снова создадим контейнер для примеров:

```bash
sudo docker run -d --name web -p 8080:80 nginx:stable
```

### 7.1. Журналы — `logs`

**Логи** — сообщения, которые приложение записывает во время работы.

```bash
sudo docker logs web
```

Просмотр новых сообщений в реальном времени:

```bash
sudo docker logs -f web
```

Остановить просмотр — `Ctrl+C`. Сам контейнер при этом продолжает работать.

### 7.2. Выполнение команды внутри контейнера — `exec`

```bash
sudo docker exec web ls /usr/share/nginx/html
```

Команда показывает файлы указанного каталога внутри запущенного контейнера.

Для входа в командную оболочку:

```bash
sudo docker exec -it web /bin/sh
```

Выйти из оболочки — `exit`. Контейнер продолжит работать.

> [!NOTE] `exec` работает с **запущенным** контейнером. Не во всех образах установлен `bash`, поэтому для Nginx используется `/bin/sh`.

### 7.3. Использование ресурсов — `stats`

```bash
sudo docker stats
```

Команда показывает текущую нагрузку контейнеров: CPU, память, сетевой ввод-вывод.

Для выхода — `Ctrl+C`.

### 7.4. Подробные сведения — `inspect`

```bash
sudo docker inspect web
```

Команда выводит технические параметры контейнера в формате JSON: состояние, настройки запуска, порты и другие сведения.

## 8. Автоматический перезапуск контейнера

**Политика перезапуска (Restart Policy)** — правило, по которому Docker автоматически запускает контейнер после определённых событий.

Например, создадим контейнер с политикой `unless-stopped`:

```bash
sudo docker run -d --name web-auto --restart unless-stopped nginx:stable
```

| Политика | Поведение |
|---|---|
| `no` | Не перезапускать автоматически (по умолчанию) |
| `on-failure` | Перезапускать при завершении с ошибкой |
| `always` | Перезапускать автоматически, в том числе после перезапуска Docker (с учётом поведения ручной остановки) |
| `unless-stopped` | Перезапускать автоматически, кроме контейнеров, остановленных вручную |
