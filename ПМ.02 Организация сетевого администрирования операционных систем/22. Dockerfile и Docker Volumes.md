## 1. Назначение Dockerfile

<mark style="background:#fff88f">**Dockerfile** — текстовый файл, содержащий инструкции для создания образа. С помощью этого файла можно создать свой образ.</mark>

<mark style="background:#fff88f">Готовые образы из Docker Hub подходят не для всех задач. Например, для запуска собственного веб-приложения может потребоваться установка дополнительных пакетов, копирование файлов и настройка рабочей директории.</mark>

## 2. Основные инструкции Dockerfile

### 2.1. Базовый образ — `FROM`

<mark style="background:#fff88f">`FROM` — инструкция выбора образа, на основе которого создаётся новый образ.</mark>

```Dockerfile
FROM ubuntu:24.04
```

<mark style="background:#fff88f">Обычно `FROM` является первой инструкцией Dockerfile.</mark>

### 2.2. Выполнение команд — `RUN`

<mark style="background:#fff88f">`RUN` — инструкция выполнения команды во время сборки образа.</mark>

<mark style="background:#fff88f">Пример:</mark>

```Dockerfile
FROM ubuntu:24.04
RUN apt update
```

>[!TIP] Особенность RUN
><mark style="background:#fff88f">`RUN` выполняется при сборке образа, а не при каждом запуске контейнера.</mark>

### 2.3. Копирование файлов — `COPY`

<mark style="background:#fff88f">`COPY` — инструкция копирования файлов и каталогов из контекста сборки внутрь образа.</mark>

<mark style="background:#fff88f">Синтаксис:</mark>

```Dockerfile
COPY ХОСТОВЫЙ_ПУТЬ КОНТЕЙНЕРНЫЙ_ПУТЬ
```

<mark style="background:#fff88f">Пример:</mark>

```Dockerfile
COPY ./index.html /usr/share/nginx/html/index.html
```

### 2.4. Рабочая директория — `WORKDIR`

<mark style="background:#fff88f">`WORKDIR` — инструкция установки рабочей директории для последующих инструкций Dockerfile и запускаемых процессов. Похожа на `cd` для перехода в директорию. Если указанной директории в контейнере ещё нет, Docker создаст её автоматически.</mark>

```Dockerfile
WORKDIR /app
```

<mark style="background:#fff88f">После этого относительные пути в инструкциях будут отсчитываться от `/app`. Пример:</mark>

```Dockerfile
FROM ubuntu:24.04
WORKDIR /app
COPY hello.txt .
```

<mark style="background:#fff88f">Файл `hello.txt` будет скопирован в `/app/hello.txt`.</mark>

### 2.5. Команда запуска — `CMD`

<mark style="background:#fff88f">`CMD` — инструкция определения команды по умолчанию при запуске контейнера.</mark>

<mark style="background:#fff88f">Пример:</mark>

```Dockerfile
FROM ubuntu:24.04
CMD ["echo", "Hello Docker"]
```

<mark style="background:#fff88f">После запуска контейнер выведет сообщение и завершит работу.</mark>

### 2.6. Документирование порта — `EXPOSE`

<mark style="background:#fff88f">`EXPOSE` — инструкция указания порта, который предполагается использовать приложением внутри контейнера.</mark>

```Dockerfile
EXPOSE 80
```

## 3. Сборка собственного Docker-образа

### 3.1. Подготовка проекта

Создание каталога:

```bash
mkdir docker-site
```

Переход в каталог:

```bash
cd docker-site
```

Создание HTML-файла:

```bash
nano index.html
```

Содержимое:

```html
<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>Docker</title>
</head>
<body>
    <h1>Мой первый Docker-образ</h1>
</body>
</html>
```

Создание Dockerfile:

```bash
nano Dockerfile
```

Содержимое:

```Dockerfile
FROM nginx:stable
COPY index.html /usr/share/nginx/html/index.html
EXPOSE 80
```

### 3.2. Сборка образа — `docker build`

<mark style="background:#fff88f">Команда создания образа на основе Dockerfile.</mark>

```
sudo docker build -t BEST_SITE:1.0 .
```

<mark style="background:#fff88f">Разбор параметров:</mark>

- <mark style="background:#fff88f">`build` — запуск процесса сборки.</mark>
- <mark style="background:#fff88f">`-t` — назначение имени и тега образа.</mark>
- <mark style="background:#fff88f">`my-nginx` — имя создаваемого образа.</mark>
- <mark style="background:#fff88f">`1.0` — тег образа.</mark>
- <mark style="background:#fff88f">`.` — текущий каталог как контекст сборки.</mark>

Во время сборки Docker последовательно обрабатывает инструкции Dockerfile.

### 3.3. Проверка образа

```
sudo docker images
```

В списке должен появиться образ `my-nginx` с тегом `1.0`.

### 3.4. Запуск контейнера

```
sudo docker run -d --name BEST_SITE -p 8080:80 my-nginx:1.0
```

Проверка:

```
curl http://localhost:8080
```

В результате должна отображаться HTML-страница, добавленная в образ.

## **6. Docker Volumes**

### **6.1. Понятие Volume**

<mark style="background:#fff88f">После удаления или повторном создании контейнера данные в контейнере будут удалены. Чтобы сохранять данные их нужно хранить вне контейнера. В Docker для этого используются **volumes** — тома, которыми управляет Docker.</mark>

<mark style="background:#fff88f">**Docker Volume** — область хранения данных, управляемая Docker и подключаемая к контейнерам.</mark>

<mark style="background:#fff88f">Данные тома сохраняются независимо от жизненного цикла контейнера. Например, можно удалить контейнер с базой данных и создать новый, подключив тот volume. Файлы базы данных останутся доступными.</mark>
