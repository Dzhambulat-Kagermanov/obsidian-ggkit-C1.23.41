## 1. Как Linux работает с дисками

### 1.1. Диск, раздел, файловая система и точка монтирования

Представим, что мы подключили к серверу новый SSD на 100 ГБ.

Физически диск существует, Linux его обнаруживает, но пользователь ещё не может просто начать сохранять туда файлы. Между физическим устройством и обычной работой с файлами есть несколько уровней.

![[Снимок экрана 2026-11-01 234912 1.png]]

- <mark style="background:#fff88f">**Диск** — устройство хранения данных. Это может быть HDD, SSD, NVMe-накопитель, виртуальный диск гипервизора или сетевое блочное устройство.</mark>
- <mark style="background:#fff88f">**Раздел** — выделенная область диска. Один диск можно разделить на несколько независимых областей.</mark>
- <mark style="background:#fff88f">**Файловая система** — способ организации файлов и каталогов на устройстве. Она определяет, как хранятся данные, имена файлов, права доступа и служебная информация.</mark>
- <mark style="background:#fff88f">**Монтирование** — подключение файловой системы к определённой директории в общей структуре Linux.</mark>

### 1.2. Почему в Linux нет дисков C: и D:?

В Windows часто используется модель:

```
C:\Windows
D:\Documents
E:\Backup
```

В Linux существует единое дерево каталогов, начинающееся с корня `/`.

Например:

```
/
├── home
├── etc
├── dev
├── opt
├── var
├── tmp
└── mnt
```

Разные каталоги могут находиться на разных физических дисках. Например:

|Каталог|Где физически хранятся данные|
|---|---|
|`/`|Системный SSD|
|`/home`|Отдельный раздел|
|`/srv/data`|Второй диск|
|`/backup`|Третий диск|

Для пользователя всё выглядит как одна файловая структура. Это удобно для серверов: администратор может добавить новый диск и подключить его к нужному каталогу, не изменяя пути, с которыми работают приложения.

Пример: веб-приложение хранит загруженные файлы в `/srv/uploads`. Если место заканчивается, администратор может перенести данные на отдельный диск и смонтировать его в тот же каталог. Приложению не обязательно знать, на каком физическом диске теперь лежат файлы.

## 2. <mark style="background:#fff88f">Зачем делить диск на разделы?</mark>

Если диск уже имеет 1 ТБ, зачем создавать на нём несколько разделов? Почему не использовать весь объём сразу?

- <mark style="background:#fff88f">Появляется возможность установить разные файловые системы на каждый раздел, например раздел `sda1` может иметь `ext4`, а раздел `sdb2` работать под `xfs`.</mark>
- <mark style="background:#fff88f">Также при разделении появляется возможность очистить конкретный раздел (например с ОС для переустановки) не затрагивая другие (например `/home`).</mark>
- <mark style="background:#fff88f">Отдельные файловые системы позволяют применять разные параметры монтирования.</mark>

>[!FAIL] <mark style="background:#fff88f">Минусы разделения. </mark>
><mark style="background:#fff88f">Предположим, администратор выделил:</mark>
>- <mark style="background:#fff88f"> `/` — 20 ГБ;</mark>
>- <mark style="background:#fff88f"> `/home` — 400 ГБ.</mark>
>
><mark style="background:#fff88f">Через некоторое время системный раздел полностью заполнился, хотя в `/home` свободно 300 ГБ. Свободное место одного обычного раздела нельзя автоматически использовать в другом.</mark>

## 3. GPT и MBR — таблицы разделов

<mark style="background:#fff88f">Перед созданием разделов на диске обычно создают таблицу разделов. Она содержит информацию о том, где начинаются и заканчиваются разделы. Есть два известных варианта — **MBR** и **GPT**.</mark>

| Характеристика              | MBR                                                  | GPT                                          |
| --------------------------- | ---------------------------------------------------- | -------------------------------------------- |
| Типичный возраст технологии | Старый формат                                        | Современный формат                           |
| Большие диски               | Ограничения около 2 ТБ при секторах 512 байт         | Поддерживает значительно большие объёмы      |
| Количество разделов         | Обычно до 4 основных, либо расширенный с логическими | Обычно до 128 записей в типовой конфигурации |
| Надёжность метаданных       | Нет резервной копии таблицы в стандартной схеме      | Резервная таблица и контрольные суммы        |
| Рекомендуемое применение    | Совместимость со старыми системами                   | Современные серверы и ПК                     |
Для новых Linux-систем обычно выбирают GPT.

## 4. Основные файловые системы Linux

После создания раздела на нём обычно создают файловую систему. Самые распространённые варианты:

| <mark style="background:#fff88f">Файловая система</mark> | <mark style="background:#fff88f">Особенности</mark>                                                        |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| <mark style="background:#fff88f">ext4</mark>             | <mark style="background:#fff88f">Универсальная, распространённая, журналируемая</mark>                     |
| <mark style="background:#fff88f">XFS</mark>              | <mark style="background:#fff88f">Хорошо подходит для крупных файловых систем и серверных нагрузок</mark>   |
| Btrfs                                                    | Поддерживает снимки, контрольные суммы данных и другие функции                                             |
| <mark style="background:#fff88f">FAT32</mark>            | <mark style="background:#fff88f">Широкая совместимость, ограничение размера одного файла около 4 ГБ</mark> |
| <mark style="background:#fff88f">exFAT</mark>            | <mark style="background:#fff88f">Удобна для обмена данными между ОС</mark>                                 |
### 4.1. Что означает журналирование?

Представим, что сервер записывает файл и внезапно отключается питание. Файловая система могла не успеть завершить обновление своих служебных структур.

<mark style="background:#fff88f">Журналируемые файловые системы, например ext4 и XFS, используют журнал для более надёжного восстановления согласованности метаданных после сбоев. Но журналирование не означает, что последние изменения файлов обязательно сохранятся, и не заменяет резервное копирование.</mark>

## 5. Что такое LVM и зачем он нужен?

<mark style="background:#fff88f">LVM (Logical Volume Manager) — система управления логическими томами Linux. Она добавляет дополнительный уровень между физическими дисками и файловыми системами.</mark>

### 5.1. Проблема обычных разделов

Предположим, на сервере есть диск объёмом 200 ГБ. Администратор выделил:

```
/       — 50 ГБ
/srv    — 150 ГБ
```

Через год данные приложений заполнили `/srv`.

Администратор подключает второй диск на 300 ГБ. Но обычный раздел `/srv` сам по себе не начнёт использовать второй диск. Потребуется перенос данных в новый 300 ГБ раздел. LVM позволяет решать такие задачи гибче.

### 5.2. Три основных понятия LVM

![[загрузка 2.svg|500]]

- <mark style="background:#fff88f">**PV (Physical Volume)** — физический том. Это диск или раздел, подготовленный для использования LVM.</mark>

- <mark style="background:#fff88f">**VG (Volume Group)** — группа томов. Она объединяет пространство одного или нескольких физических томов в общий пул.</mark>

- <mark style="background:#fff88f">**LV (Logical Volume)** — логический том. Это виртуальное блочное устройство, которое администратор создаёт из пространства группы томов. На нём можно создать файловую систему и смонтировать её.</mark>

### 5.3. Зачем нужна группа томов?

Представим, что у сервера есть два диска:

```
Диск 1: 100 ГБ
Диск 2: 200 ГБ
```

Мы добавляем оба в группу `vg_data` и получается что `vg_data` теперь содержит 300 ГБ.

Теперь LVM может выделять логические тома из общего пространства группы. Например:

```
lv_files   — 150 ГБ
lv_backup  — 100 ГБ
Свободно   — около 50 ГБ
```

Если файловому хранилищу потребуется больше места, можно использовать свободное пространство группы. Если его не хватит, администратор может добавить ещё один диск в `vg_data` и расширить LVM группу. 

>[!SUCCESS] Преимущество LVM:
>Гибкое распределение дискового пространства.

>[!FAIL] Минусы LVM:
>Если обычный LVM-том использует данные с нескольких физических дисков, отказ одного из них может привести к потере доступности всего тома.
